# FSD — кейсы размещения (шпаргалка)

> Собрана по запросу перед экзаменом главы 1.2: «набор кейсов от простого к сложному, на все случаи жизни». Порядок таблицы = порядок роста проекта: минимум `shared + pages + app` → сущности → фичи → границы → масштаб/легаси. Связана с [[FSD — слои и правило импортов]], [[FSD — сегменты]], [[FSD — слайсы и группы слайсов]], [[FSD — public API и barrel files]], [[FSD — кросс-импорты и стратегии]].

## Позвоночник: четыре вопроса

1. **Есть бизнес-контекст?** Нет → `shared` (или `app`, если дело всего приложения). Да → дальше.
2. **Сколько потребителей?** Один → слайс страницы. Несколько → общий слой.
3. **Существительное или глагол?** Существительное (данные + вид) → `entities`. Глагол (действие) → `features`.
4. **Импорт только строго вниз?** Тянет в сторону/вверх → уровень 5 (границы).

## Уровень 1 — старт: фундамент без бизнеса

| Кейс | Куда | Критерий |
|---|---|---|
| UI-кит: Button, TextField, Modal; автокомплит, строка поиска (UI-логика) | `shared/ui` | переиспользуемый UI **без бизнес-логики**; «бизнес-тематическое» (логотип, каркас страницы) — допустимо [Layers] |
| Форматтер дат/денег, плюрализация «3 товара» | `shared/lib` | библиотека **одной области ответственности**, не «utils» [Layers] |
| Обёртка fetch, API-клиент | `shared/api` | связь с внешним миром: бэкенды, библиотеки [Layers] |
| ENV, глобальные feature-флаги, переводы | `shared/config`, `shared/i18n` | глобальная конфигурация [Layers] |
| Конфигурация роутера, провайдеры, глобальные стили | `app` (`routes`, `store`, `styles`) | дела всего приложения [Layers] |
| Аналитика | `app` | бизнес-дело всего приложения [Layers] |
| Простая шапка-навигация | `shared/ui` | «каркас страницы» допустим; без бизнес-логики (визуализатор, шаг 6.3) [Layers] |
| Шапка-композиция: юзер + меню + поиск | `app` | «UI уровня всего приложения (глобальные лейауты) — в app» [Layers] |

## Уровень 2 — экран целиком в своём слайсе

| Кейс | Куда | Критерий |
|---|---|---|
| Запрос данных этого экрана (теги ленты) | `pages/feed/api` | один потребитель [туториал] |
| Пагинация/табы одного каталога | `pages/catalog/ui` | нерелюзнутый UI-блок — нормально внутри слайса [Layers] |
| Состояние экрана (выбранный тег) | `pages/feed/model` | локальное состояние экрана [туториал] |
| Валидация формы статьи | `pages/article-edit/model` | внутренность слайса, наружу не торчит 🟡 |
| Комментарии только на странице статьи | `pages/article-read` | один потребитель; «не всё — фича» [FAQ] |
| «Настройки пользователя» | `pages/settings` | экран-композиция; данные юзера — `entities/user` 🟡 |

## Уровень 3 — общее с бизнес-контекстом (entities)

| Кейс | Куда | Критерий |
|---|---|---|
| Тип `Article` нужен двум слайсам | `entities/article/model` | «понятие реального мира»; в shared нельзя — там нет бизнес-доменов [Layers] |
| Превью статьи в ленте и в профиле | `entities/article/ui` | «переиспользовать один и тот же вид в нескольких страницах» [Layers] |
| Запросы «статьи автора», «по slug» | `entities/article/api` | API-функции сущности [Layers] |
| Корзина: данные + иконка с бейджем | `entities/cart` | существительное; **сложность — не критерий** [FAQ, Slices] |

## Уровень 4 — переиспользуемые действия (features)

| Кейс | Куда | Критерий |
|---|---|---|
| Лайк на странице статьи и в ленте | `features/favorite-article` | «пользователь хочет [глагол] [сущность]»; индикатор — переиспользование на страницах [FAQ] |
| add-to-cart / remove-from-cart | `features/*` | юз-кейсы; cart-DTO и мапперы — домен (`entities/cart`) [Slices] |
| Поиск по сайту на всех страницах | `features/search` | переиспользуемое действие 🟡 |

## Уровень 5 — границы: соседи, @x, круги

| Кейс | Куда | Критерий |
|---|---|---|
| Соседней странице нужен твой `TagList` | свой `TagList` в своём слайсе | слайсы одного слоя не знают друг друга (zero coupling); дублирование осознанное [туториал] |
| `article` нужен тип `Profile` (автор) | сначала рассмотреть слияние; если нет — `entities/profile/@x/article.ts` | кросс-импорты — минимумом, только на entities [Public API] |
| Форма импортирует из `"../"` (index слайса) | полные относительные пути внутри слайса | иначе circular: index → форма → index [Public API] |
| Логика взаимодействия двух сущностей | выше: `features` / `pages` | «бизнес-логику взаимодействий предпочтительно держать выше» [Layers] |
| checkout + promo на одном экране | слияние / вынести в домен / композиция страницей | четыре стратегии кросс-импортов; строгость — решение команды [Cross-imports] |

## Уровень 6 — масштаб и легаси

| Кейс | Куда | Критерий |
|---|---|---|
| В features десятки слайсов | группы: `features/payments/{recurring,refunds}` | slice groups: в группе юз-кейсы + домен [Slices] |
| Модуль нужен по-разному на SSR и клиенте | `index.server.ts` / `index.client.ts` | environment-specific public API [§6.3 главы] |
| Миграция легаси-проекта | 1) App/Shared модуль за модулем → 2) Pages «широкими мазками», даже с нарушениями → 3) постепенно чинить, извлекать entities/features | инкрементальное внедрение; новых больших сущностей в период рефакторинга не заводить [Overview] |
| «Заведём слой widgets» | нет: композиция экрана → `pages`; действие → `features`; UI без бизнеса → `shared`; глобальный лейаут → `app` | справочник отговаривает: граница с features размыта [Layers] |
