# FSD — сегменты

> Подглава 5 главы 1.2 курса «Фронтенд senior+ в агентную эру». Якорь [FSD] — Reference → Slices and segments. Продолжает: [[FSD — слайсы и группы слайсов]].

## Executive Summary (ELI5)

Сегмент — третий и последний уровень иерархии: **группировка кода по технической природе**. Слой — «какая ответственность», слайс — «какой домен», сегмент — «какая техническая роль в домене».

## Пять конвенциональных сегментов

| Сегмент | Содержимое (по источнику) |
|---|---|
| `ui` | всё про отображение: UI-компоненты, **форматтеры дат**, стили |
| `api` | взаимодействие с бэкендом: функции запросов, **типы данных (DTO), мапперы** |
| `model` | модель данных: схемы, интерфейсы, сторы, бизнес-логика |
| `lib` | библиотечный код, нужный **другим модулям этого слайса** |
| `config` | конфигурационные файлы, feature-флаги |

Две ловушки:
- **Форматтеры дат → `ui`**, не `lib`/`model` (они про отображение — прямо в определении источника).
- **DTO → `api`** (data types — часть api-сегмента), а `model` — доменные схемы/интерфейсы/сторы. Транспортный тип ≠ доменный тип.

`lib` слайса vs `shared/lib`: внутрислайсовый `lib` — код только этого домена (проверка Луна для чекаута); нужен нескольким доменам → `shared/lib` (`debounce` для поиска и фильтров).

Кастомные сегменты можно — чаще всего в **App и Shared** (где слайсов нет): `i18n`, `routes`, `entrypoint`.

## Правило именования: purpose, не essence

> Имя сегмента описывает **назначение («зачем»), а не сущность («что это»)**. `components`, `hooks`, `types` — плохие имена: не помогают искать код.

`components/` отвечает «что за файлы», `ui/` — «для чего». `types/` + `store/` + `logic/` — три essence-папки вместо одного purpose-сегмента `model/`.

Четыре последствия essence-имён (по источнику):
1. перелопачиваешь каждый файл, чтобы понять содержимое;
2. несвязанный код лежит рядом (`src/hooks/` = 40 хуков всех доменов);
3. области рефакторинга расширяются;
4. ревью и тестирование усложняются.

## Пример из реального продукта (🟡 иллюстрация курса)

`features/add-to-cart` в клоне Ozon: `ui` — кнопка «В корзине ✓» · `api` — POST /cart/items + маппер · `model` — стейт «добавляется/добавлено» · `lib` — расчёт позиции корзины (только этому слайсу) · `config` — флаг нового дизайна.

## Self-check

1. Пять сегментов? → ui (с форматтерами!), api (с DTO и мапперами), model, lib, config.
2. Куда DTO? → api. Куда форматтер дат? → ui.
3. Почему components/hooks/types — плохо? → essence вместо purpose + 4 последствия.
