# ⚡ Core Web Vitals — пороги (good / needs improvement / poor)

> [!abstract] Executive Summary (ELI5)
> **Core Web Vitals (CWV)** — это три метрики Google, которые измеряют ключевые аспекты UX страницы: **загрузку главного контента (LCP)**, **интерактивность (INP)** и **визуальную стабильность (CLS)**. Для каждой есть три зоны: 🟢 good / 🟡 needs improvement / 🔴 poor. Пороги — это **полевые данные (field data)**: 75-й перцентиль загрузок страницы за 28 дней. То есть «good» = 75% визитов укладываются в порог.

> Источник: якорь [web.dev] (будет пройден в главе 6.3 «Производительность: CWV, бюджеты, профайлинг»). Здесь — справочные пороги для ADR и собеседований.

---

## 🎯 The "Why"

- **Зачем знать наизусть:** на senior-собеседовании по производительности фронтенда (и в system design) ожидается, что ты называешь конкретные числа, а не «ну, страница должна грузиться быстро». CWV — это **общий язык** между фронтом, продактами и SEO.
- **Как использовать в ADR:** NFR по производительности формулируется не «страница должна быть быстрой», а «LCP ≤ 2.5s на 75-м перцентиле». Это измеримая цель, по которой потом (глава 6.3) меряются perf-бюджеты.

---

## 💡 Mental Model

CWV — это **три разных оси UX**, не три варианта одной метрики:

| Метрика | Что измеряет | UX-вопрос |
|---|---|---|
| **LCP** | загрузка главного контента | «Когда пользователь ВИДИТ то, ради чего пришёл?» |
| **INP** | интерактивность (отклик на действия) | «Когда страница НАЧИНАЕТ ОТВЕЧАТЬ на клики?» |
| **CLS** | визуальная стабильность | «Не „прыгает“ ли контент под палец?» |

```
Загрузка ──────► LCP   (контент виден)
            │
            ▼
Готовность ──► TTFB  (сервер ответил первым байтом — вспомогательная, не CWV)

Интерактив ─► INP   (отклик на действие во время сессии)

Стабильность► CLS   (сколько контент «сдвинулся» за время загрузки)
```

## 📊 Пороги CWV (field data, 75-й перцентиль за 28 дней)

### LCP — Largest Contentful Paint

> Самый крупный видимый элемент (hero-картинка, заголовок, видео-плакат) отрисован.

| Зона | Порог |
|---|---|
| 🟢 Good | **≤ 2.5 s** |
| 🟡 Needs improvement | ≤ 4.0 s |
| 🔴 Poor | > 4.0 s |

**Что влияет:** серверный рендеринг (HTML в первом ответе ускоряет), размер изображений, блокирующие ресурсы, шрифты. Поэтому в ADR StyleNest выбор SSG/PPR для витрины прямо бьёт по LCP.

### INP — Interaction to Next Paint

> Время от действия пользователя (клик, тап, ввод) до следующей отрисовки, берётся **худшее** (или близкое к худшему) взаимодействие за всю сессию.

| Зона | Порог |
| 🟢 Good | **≤ 200 ms** |
| 🟡 Needs improvement | ≤ 500 ms |
| 🔴 Poor | > 500 ms |

> [!important] INP заменил FID
> **FID (First Input Delay)** был Core Web Vital до **марта 2024**. INP — более строгий: FID мерял только задержку **первого** взаимодействия, INP меряет **все** взаимодействия за сессию и берёт худшее. На собеседовании: «INP с марта 2024 — это замена FID, потому что FID не ловил медленные интеракции после первой».

**Что влияет:** длинные задачи на главном потоке, дорогая гидратация (uncanny valley SSR — §3.4), обработчики событий. Отсюда Selective Hydration / RSC / Islands прямо бьют по INP.

### CLS — Cumulative Layout Shift

> Сумма всех «сдвигов» контента за время жизни страницы (от загрузки до скрытия). Безразмерная.

| Зона | Порог |
| 🟢 Good | **≤ 0.1** |
| 🟡 Needs improvement | ≤ 0.25 |
| 🔴 Poor | > 0.25 |

**Что влияет:** изображения/видео без `width`/`height`, динамические блоки без зарезервированного места (рекомендации, баннеры), веб-шрифты (FOUT/FOIT), реклама. Skeleton UI и резервирование места под Server Islands — прямой рычаг.

## 🧭 Вспомогательные (НЕ Core Web Vitals, но важные)

### TTFB — Time to First Byte

> Время от запроса до первого байта ответа. **Не входит в тройку CWV**, но это корневая метрика: LCP не может быть быстрее TTFB.

| Зона | Порог |
|---|---|
| 🟢 Good | **≤ 800 ms** |
| 🟡 Needs improvement | ≤ 1800 ms |
| 🔴 Poor | > 1800 ms |

**Связь с главой 1.1:**
- Static/SSG (CDN) → минимальный TTFB.
- SSR per-request → медленный TTFB (work happens per request, §3.2).
- Edge SSR → TTFB ~30–80 ms vs ~200–600 ms на централизованном origin (§3.6).

---

## 🧠 Запомнить для собеседования (3 ключевых числа)

1. **LCP ≤ 2.5 s** — «главный контент виден за 2.5 с».
2. **INP ≤ 200 ms** — «отклик на действие за 200 мс» (заменил FID в марте 2024).
3. **CLS ≤ 0.1** — «контент не сдвигается больше чем на 0.1».

> [!tip] Мнемоника
> «**2.5 / 200 / 0.1**» — секунды / миллисекунды / безразмерно. Единицы разные — это и помогает запомнить, что метрики разные.
