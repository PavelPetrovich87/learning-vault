# Организация кода — сводка выбора и failure modes

> Подглава 12 главы 1.2 — капстоун главы: правила «когда что применять» + десять типовых ошибок. Собирает всё: [[FSD — зачем архитектура (проблемы и требования)]], [[FSD — слои и правило импортов]], [[FSD — public API и barrel files]], [[FSD — кросс-импорты и стратегии]], [[Atomic Design — системы, а не страницы]], [[Atomic Design — пять уровней интерфейса]], [[Скрещивание — FSD × Atomic Design × DDD-light]].

## Когда что применять (по источникам)

1. **FSD подходит, если это фронтенд-приложение (не библиотека); фреймворк/язык/стейт-менеджер не важны.** [FSD] Overview
2. **Мигрировать — только когда текущая архитектура причиняет боль** (медленный онбординг, большой бласт-радиус, непредсказуемые изменения). §1.1, §2.1
3. **Начинать с минимума слоёв: App + Pages + Shared**; добавлять слои, когда приносят ценность. [FSD] Layers
4. **Миновать `processes` (deprecated) и осторожно с `widgets`** (граница с features размыта). [FSD] Layers — ⚠️ это НЕ про features/entities: те — полноправные слои, добавляемые по мере необходимости.
5. **AD — внутри `ui`-сегментов**: молекула — «делай одно дело хорошо»; организм — переиспользуемая секция; шаблон — скелет страницы. [FSD] FAQ + [AD] гл. 2
6. **Декомпозиция сверху: страницы → крупные области → общее извлекать по ходу разработки, не заранее.** [FSD] Tutorial

## Десять failure modes (+ механика «что ломается»)

**Блок FSD — нечестные границы:**

1. **«Всё — фича».** Механика: слишком много фич топит важные области кода; индикатор фичи — переиспользование на нескольких страницах.
2. **Свалка в `shared`.** Механика: dump без границы приёма → нет владельца, широкий бласт-радиус, непрозрачные ревью; lib-библиотеки без области ответственности — то же самое.
3. **Сегменты по essence** (`components/`, `hooks/`, `types/`). Механика: имя не говорит, что сегмент делает; навигация и поиск по смыслу невозможны — называй по purpose.
4. **Wildcard-реэкспорты** (`export *`). Механика: не видно, что слайс экспортирует (discoverability), безопасный рефакторинг невозможен — неизвестны потребители.
5. **Barrel files в сегментах / один общий index в `shared/ui`.** Механика: циклические импорты, сломанный tree-shaking (бандл тащит лишнее), медленный dev-сервер.
6. **Кросс-импорт как норма.** Механика: путь к циклам и неясному владению; прежде чем `@x` — стратегии A–D (merge → домен в entities → композиция сверху → только public API).
7. **Группа слайсов как «домен».** Механика: общий код в группе слайсов запрещён — группа это только навигация; начнёшь класть общее → скрытая связь между слайсами.

**Блок AD — смешение модели с процессом:**

8. **AD как линейный процесс** («сначала все атомы…»). Механика: waterfall по уровням блокирует поставку; методология работает уровнями одновременно.
9. **Слишком много энергии в метафоры AD.** Механика: энергия уходит в таксономию/картинки вместо проектирования систем.
10. **Проектирование страниц вместо систем.** Механика: «30 000 страниц» не оцениваются компонентами; каждое новое «похожее» плодит копипасту вместо переиспользования.

**Два вопроса на ревью, ловящие 9 из 10:** «граница честная?» (ловит 1–7) и «это система или набор страниц?» (ловит 8–10).

## StyleNest: вероятные failure modes при FSD-миграции

🟡 Применение к курсу: (а) **свалка в `shared`** — витрина маленькая, соблазн «пусть полежит в shared» максимален; профилактика: lib-под-библиотеки с одной областью и README, правило приёма; (б) **кросс-импорты** — с появлением `entities/cart` рядом с `entities/product` (собственная ошибка §3 Q1: разрешил `entities/cart → entities/product`); профилактика: порядок «слияние → @x», линтер границ; (в) **«всё — фича»** — с добавлением интерактива (избранное, корзина); профилактика: тест «существительное vs глагол» и индикатор переиспользования.

## Self-check

1. Главный критерий применимости FSD? → фронтенд-приложение (не библиотека); фреймворк/стейт не важны.
2. Какие два слоя миновать и почему? → processes (deprecated), widgets (размытая граница с features) — НЕ features/entities.
3. Десять failure modes — по механике? → см. выше; FSD-блок = нечестные границы, AD-блок = модель↔процесс.
4. С чего начинать декомпозицию? → сверху: страницы → области → общее по ходу, не заранее.
