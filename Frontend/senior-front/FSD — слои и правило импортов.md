# FSD — слои и правило импортов

> Подглава 3 главы 1.2 курса «Фронтенд senior+ в агентную эру». Якорь [FSD] — Reference → Layers. Продолжает: [[FSD — обзор методологии]].
> По решению пользователя: `processes` (deprecated) и `widgets` (не рекомендуется справочником) — не разбираются; упоминаются одной строкой, чтобы не удивляться в чужих кодбазах.

## Executive Summary (ELI5)

Слои — первый уровень иерархии FSD. Делят код по **объёму ответственности** и **числу зависимостей**: сверху — то, что знает про всё приложение; снизу — то, что не знает ни о чём доменном.

## 7 слоёв (сверху вниз)

1. **App** — роутинг, точки входа, глобальные стили, провайдеры, аналитика.
2. *Processes — deprecated в актуальной спеке (не используем).*
3. **Pages** — страницы/скрины; или большие части страницы во вложенном роутинге.
4. *Widgets — справочник отговаривает: граница с features размыта (не используем).*
5. **Features** — переиспользуемые реализации целых продуктовых фич — действий с бизнес-ценностью.
6. **Entities** — бизнес-сущности: `user`, `product`, `cart`, `review`.
7. **Shared** — переиспользуемый код, отделённый от специфики проекта.

- **Не обязательно использовать все слои**; минимум большинства проектов — **Shared + Pages + App**.
- Добавлять свои слои **не рекомендуется** — семантика стандартизирована.

## Правило импортов — ядро методологии

> *A module (file) in a slice can only import other slices when they are located on layers **strictly below**.*

Пример справочника: `features/aaa/api/request.ts` НЕ может импортировать `features/bbb` (тот же слой), МОЖЕТ — `entities`, `shared` и свой слайс (`features/aaa/lib/cache.ts`).

⚠️ **Следует и для entities:** `entities/cart → entities/product` — тоже запрещено (слайсы одного слоя). Разрешение таких ситуаций — кросс-импорт-стратегии (слияние слайсов, `@x`) — отдельная тема (§7 главы).

**Исключения — App и Shared:** одновременно слой и слайс. Причина: слайсы делят по бизнес-доменам, а у Shared доменов нет, App — объединяет все. Следствие: внутри них сегменты импортируют друг друга свободно.

## Семантика слоёв

### Shared
Фундамент: связь с внешним миром (бэкенды, библиотеки, окружение) + собственные самодостаточные библиотеки. Сегменты: `api` (клиент, запросы), `ui` (UI-кит: без бизнес-логики, но бизнес-тематический — ок; UI-логика разрешена — autocomplete, плеер-примитив), `lib` (**не utils!** каждая библиотека — одна область: даты/цвета/текст + README), `config`, `routes`, `i18n`.

### Entities
**Существительные**: понятия реального мира, термины бизнеса. Слайс: `model` (хранилище, схемы), `api`, `ui` (вид для переиспользования на нескольких страницах, бизнес-логика — пропсами/слотами; не обязан быть законченным блоком).

### Features
**Глаголы**: главные взаимодействия — «то, что пользователи хотят делать с сущностями» (FAQ). Тест: *«пользователь хочет [ГЛАГОЛ] [СУЩЕСТВИТЕЛЬ]»*. Индикатор фичи — **переиспользование на нескольких страницах**; «не всё — фича»; оптимизируй структуру под новичка. Слайс: `ui`, `api`, `model`, `config`.

⚠️ **Сложность — НЕ критерий.** Корзина «работает с набором сущностей» — всё равно сущность (`entities/cart`: данные + вид). Действия над ней — фичи (`add-to-cart`, `remove-from-cart`). Подкрепление источника (slice-groups): add-to-cart/remove-from-cart — юз-кейсы, а cart-DTO/мапперы — домен.

### Pages
Один экран — один слайс (похожие можно сгруппировать: login+register). Размер не лимитирован, пока легко навигировать; **нерелюзнутый UI-блок — нормально держать внутри слайса страницы** (пагинация только каталога → `pages/catalog/ui`). Типично: `ui` (+ loading/error состояния), `api`; отдельная `model` нехарактерна.

### App
Дела всего приложения: технические (провайдеры) и бизнесовые (аналитика). Сегменты: `routes`, `store`, `styles`, `entrypoint`.

## Раскладка реального продукта (🟡 иллюстрация курса, не из доков FSD)

YouTube: `app` — роутер/провайдеры/аналитика · `pages` — home, watch, search, subscriptions · `features` — like, subscribe, add-to-playlist · `entities` — video, channel, comment, playlist · `shared` — ui-кит, api-клиент, lib (formatDuration: «10:03»), config, i18n.

Пограничный кейс 🟡: **видеоплеер** расслаивается: технический (обёртка над движком) → `shared/ui` («components with UI logic are allowed»); доменный → `entities/video/ui` (вид сущности) или `features/watch` (просмотр как действие) — решает команда, оба варианта легальны. В курсе вернётся на видеоплатформе (гл. 1.8 statecharts).

## Куда класть общее для нескольких слайсов (критерий shared vs entities)

Кейс визуализатора (этап 5): `ArticlePreview` нужен и ленте, и профилю. Перебор мест:

1. **Слайс pages** — нельзя: второму потребителю нужен импорт из соседнего слайса того же слоя (zero coupling, запрещено).
2. **shared** — нельзя. Напрямую: компоненту нужен бизнес-тип `Article` с верхнего слоя → импорт вверх, красная стрелка. Хитрый обход — утащить в shared и сам тип: правило импортов промолчит (все зависимости вниз), но нижний слой узнаёт о бизнесе, следом просятся Profile/Comment/Tag — свалка 🟡. Критерий shared — **семантический**, не механический: «не содержит слайсов (бизнес-доменов здесь не существует)».
3. **entities** — ровно этот случай: «понятия реального мира»; главная цель `ui` сущности — переиспользовать один и тот же вид в нескольких страницах, разная бизнес-логика — пропсами/слотами.

Литмус-тест 🟡: «перенёс бы файл в другой проект без правок?» Button / fetch-обёртка / форматтер дат — да; `ArticlePreview` / `Article` — нет. Правило импортов ловит только импорты вверх; «бизнес утёк в shared» оно не видит — за это отвечает семантика слоя.

## Self-check

1. `features/cart → entities/product`? → да (ниже). `entities/product → features/cart`? → нет (вверх). `entities/cart → entities/product`? → **нет** (один слой!).
2. Корзина — сущность или фича? → сущность; сложность не критерий; фичи — действия над ней.
3. UI-блок одной страницы — куда? → внутрь слайса страницы; переиспользуемый без бизнес-контекста — `shared/ui`.
4. `ArticlePreview` нужен двум страницам — куда? → `entities/article/ui`. В shared нельзя: даже «хитрый» вариант с переносом туда типа `Article` кладёт бизнес-контекст на слой без бизнес-доменов — правило импортов это не ловит, критерий семантический.
