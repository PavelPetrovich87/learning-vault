# 2.7 Ranking Multiple Inputs — Flashcards

<!-- Три входа ранжирования пробелов? :: -->
<!-- 1) Ценность против усилий; 2) основа для других возможностей — закрытие окупается дважды: прямая польза плюс всё, что другие возможности построят на ней; 3) действующая уязвимость — данные уже идут туда, куда никто не смотрит. -->
<!-- #flashcards/ai-consulting/module-2 -->

<!-- Почему пробел-основа может обогнать более ценный одиночный пробел? :: -->
<!-- Закрытие окупается дважды: кроме прямой пользы оно создаёт основу, которую другие возможности будут использовать повторно. -->
<!-- #flashcards/ai-consulting/module-2 -->

<!-- Почему действующая уязвимость может обогнать ценный, но безопасный пробел? :: -->
<!-- Цена ожидания различна: при живой уязвимости (данные уже идут туда, куда никто не смотрит) каждый день ожидания дороже. -->
<!-- #flashcards/ai-consulting/module-2 -->

<!-- Что даёт тест «убери один вход» в каждом из двух исходов? :: -->
<!-- Не изменился ни при одном изъятии — список ранжировался одним фактором, многофакторность была ложной: принять однофакторность осознанно или оценить недостающие входы. Изменился при изъятии X — решение чувствительно к X: проверить обоснованность оценок X до бюджета; спор о списке — спор о X. По построению это анализ чувствительности. -->
<!-- #flashcards/ai-consulting/module-2 -->

<!-- Четвёртый вход, который пропускают чаще всего? :: -->
<!-- Что организации придётся сопровождать после закрытия пробела. Он же определяет способ закрытия: adopt или build. -->
<!-- #flashcards/ai-consulting/module-2 -->

<!-- Правило выбора между готовым решением и собственной разработкой? :: -->
<!-- Потребность массовая, решённая на рынке, слабо связанная со своими системами — по умолчанию готовое решение. Специфическая, повторяющаяся, глубоко связанная с работающей системой — строить: исключение, которое имеет смысл. -->
<!-- #flashcards/ai-consulting/module-2 -->

<!-- Почему каждая собственная разработка несёт план вывода из эксплуатации с первого дня? :: -->
<!-- Поставщики платформ почти в каждом релизе встраивают соседние возможности — собственная постройка рано или поздно поглощается платформой, и нужно уметь уйти без потерь. -->
<!-- #flashcards/ai-consulting/module-2 -->

<!-- Какова цена способности переключиться на другое решение? :: -->
<!-- Не бесплатна: требует постоянных вложений. Организация, никогда не решившая сохранять гибкость, обычно уже заперта в зависимости — и не заметила этого. -->
