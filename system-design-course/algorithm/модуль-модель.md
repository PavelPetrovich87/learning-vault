# Модуль МОДЕЛЬ — структура зафиксирована ✅ · наполнение 4/5 (раунды 3–4)

> Заметка-модуль алгоритма [[Алгоритм выбора решений]] · диаграмма: `карта-алгоритма.drawio` (рядом)
> Шаблон спецификации: Назначение / Контракт / Состояние / Инварианты / Рендеры. Статус «структура зафиксирована» = каркас собран, часть-заглушка ждёт своего шага цикла (термины — в [[словарь]]).

**Назначение.** Рабочее состояние алгоритма: всё, что мы считаем и пересчитываем в ходе цикла.

**Контракт.** Read-write. Внутренняя иерархия: одно состояние первично, остальные — производные от него и рамки. Производные реестры **руками не правятся** — это тень состава и рамки (защита от «таблица молча стала контрактом»).

**Состояние.**

- **Состав (первичное) — ✅ прогрилован (раунд 3).** Роли-носители обязанностей + связи-обмены. Технологически стерилен. Модификация состава — только шаг 1, через названную боль.
- **Оценщик — ✅ прогрилован (раунды 3, 8).** Детерминированный вычислитель реестра болей, решений не принимает — только фиксирует нарушения. Считает записи (класс — из шкалы рамки, доля — из параметров нагрузки) **и сортирует реестр в очередь** по мере серьёзности. Три исполнения: **примерные расчёты** (интервью: Литтл, параметры нагрузки, таблица латентностей вслух), **расчёт** (RFC), **прогон** (симулятор / нагрузочный тест / мониторинг). Симулятор саги — буквально ручной оценщик: диспозиция → прогон → отчёт → вердикт.
- **Реестр болей (производное) — ✅ прогрилован (раунды 3, 8).** `боль = f(требование из рамки × сценарий из рамки × текущий состав)`. Пересчитывается при любой модификации состава и при уточнении/торге в рамке. Руками не правится. Отдаётся шагу 1 **очередью** — записями, отсортированными по мере серьёзности (правило — в подразделе ниже).
- **Реестр вопросов (производное, выход наружу; прежде «реестр запросов» — переименован 2026-09-07, слово «запрос» освобождено под единицу работы) — ✅ прогрилован (раунд 4).** Список «что добыть вовне»: `{какое число · у кого · какой вопрос · какая развилка на нём висит · что подставлено на время}`. Пишут оценщик (два триггера: **нет входа** — считать нечего; **чувствительное предположение** — ×2/÷2 переворачивает развилку, а источник «мы сами придумали») и шаги; читает проектировщик. Поле «развилка» обязательное — это оправдание вопроса; именно оно делает предположение сеньорским ходом: «приму 5 действий в день; если вдвое больше — другая архитектура; уточним?». Режимы реакции: **блокирующий** (остановиться и сходить за ответом — реальная работа) и **в долг** (консервативная подстановка, вопрос висит — на интервью проговор вслух и есть «в долг»). Гаснет при уточнении/торге → модель пересчитывается → часть вопросов гаснет, развилки обновились, возможен новый виток.
- **Прочие производные — ⬜ заглушка.** Нагрузка на роли, декомпозиция бюджетов, ёмкость (слоты), цены кандидатов — пишутся шагами 2–4, читаются 5–6. Наполнение: нагрузка на роли, бюджеты ролей и ёмкость — наполнены шагом 2 (2026-09-07); цены кандидатов → шаги 3–5.

### Правило серьёзности — реестр болей отдаётся очередью

Сортировку исполняет оценщик при каждом пересчёте реестра: это детерминированное вычисление без проектных решений — «шаги решают, оценщик считает». Шкала последствий (рамка) работает дважды: оценщик выбирает из неё класс каждой боли, а её порядок — критерий №1 сравнения; сама шкала о болях не знает. Шаг 1 получает готовую очередь и никуда не ходит: ни в рамку, ни к оценщику.

**Алгоритм — сравнение двух болей:**
1. **Класс.** Чей класс стоит раньше в шкале последствий — тот выше в очереди.
2. **Класс равен → доля.** У кого доля затронутого больше — тот выше.
3. **Равны оба → порядок безразличен.**

Складывать нельзя ни классы (шкала порядковая: «страшнее / не страшнее», не числа), ни доли (общие пострадавшие посчитаются дважды). Самопроверка: порядок очереди пересказывается одним предложением («сначала всё, что теряет данные, потом что роняет, потом что тормозит — внутри группы по числу пострадавших»).

**Классы — референс** (порядок = шкала из рамки, поле «шкала последствий»; проектовый порядок подтверждает владелец: «что для нас необратимо?»; деньги — не класс, это цена решений шагов 4–5):

| Класс | Что происходит | Пример | Откатываемо? |
|---|---|---|---|
| Теряет данные | невосполнимая утрата | пропал платёж, черновик | нет |
| Роняет всё | система недоступна целиком | отказ единственного узла | да, простоем |
| Деградирует | части функций хуже | поиск 5 с вместо 0.5 с | да |

**Доля** — скольким станет хуже, в % от работы системы: у НФТ — доля запросов или пользователей, кому хуже («поиск > 2 с при пике», поиск = 30% запросов → 30%); у ФТ — доля действий, которым нужна функция («нет экспорта отчётов», 5% действий → 5%).

**Очередь по дефолтной шкале (пример):**

| # | Боль | Класс | Доля |
|---|---|---|---|
| 1 | сбой записи теряет платежи | теряет данные | 10% операций |
| 2 | теряются черновики | теряет данные | 1% пользователей |
| 3 | отказ единственного узла роняет систему | роняет всё | 100% |
| 4 | поиск дольше 2 с на пике | деградирует | 30% запросов |
| 5 | нет экспорта отчётов (ФТ) | деградирует | 5% действий |

№3 ниже №1–2 при доле 100% — сработал шаг 1 алгоритма (класс сильнее доли); №1 выше №2 — сработал шаг 2 (доля при равном классе).

**В сортировку не входит:**
- **кратность** — сколько экземпляров роли родить (×N): «терять данные» страшно и при ×1;
- **проверочные сценарии кратностью** — скачок/отказ/деплой рождают свои боли, оцениваемые теми же классом и долей; класс и доля считаются при самой тяжёлой проектирующей нагрузке — пике на горизонте роста.

**Внутренняя петля.** Цикл пишет состав → модификация пересчитывает реестры → цикл читает реестр для следующего хода.

**Инварианты.**

1. Производные реестры не правятся руками — только пересчётом.
2. Каждое число модели имеет формулу от рамки и решений (правило двух источников — модуль РАМКА, «Граница с моделью»).
3. Пустой реестр вопросов при живых долгах — красный флаг: «дизайн без открытых вопросов = самообман».

**Рендеры.** Доска/бумага (таблицы), симулятор саги (ручной оценщик), панель инструмента. Структура не зависит от носителя.
