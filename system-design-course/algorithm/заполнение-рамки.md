# Заполнение рамки

> Под-заметка модуля [[модуль-рамка|РАМКА]] алгоритма [[Алгоритм выбора решений]] · диаграмма этапа: `заполнение-рамки.drawio` (рядом) · место на общей карте: `карта-алгоритма.drawio`.
> **Статус:** ⬜ черновик — переработан по решению владельца 2026-10-03 (первая версия 2026-09-15, тогда называлась «заполнение рамки (интервью)»), ждёт гриллинга. Термины-кандидаты в словарь: опрос · анкета · детектор · щуп · цель · протокол опроса · раскладка.

**Назначение.** Этап заполняет рамку — единственную дверь, через которую внешние данные попадают в алгоритм.

## Участники

| Роль | Что делает |
|---|---|
| проектировщик | исполняет этап: ведёт опрос, предлагает кандидатов, пишет протокол |
| владелец числа | отвечает на вопросы; **только он** записывает значения в рамку (операции уточнение/торг — контракт РАМКИ) |
| справочник | даёт порядки величин для технических кандидатов |

Запуски этапа: **первичный опрос** (старт проекта — шаги 1–7) и **до-заполнение** (ответ владельца пришёл по ходу проекта — шаги 5–7 для одной строки).

## Вход

| Часть | Содержимое |
|---|---|
| **источник** | текст (бриф) · живой человек (интервьюер/заказчик) · никто |
| **данные** | мешанина фракций: числа без владельцев · ярлыки без чисел · готовые факты · дыры (темы, о которых не сказано ничего) — либо чистое молчание |
| **сущности домена** | перечень вещей, вокруг которых крутится продукт; приносит проектировщик — единственное место алгоритма, где опыт человека входит легально |

## Выход

1. **рамка** с заполненными полями 1–5 (инварианты рамки выполнены);
2. **протокол опроса** — все строки с судьбами;
3. **реестр вопросов** — строки, ушедшие наружу (модель).

## Алгоритм

**Шаг 1 — режим по источнику** (единственная развилка). Источник «человек», текста нет → режим **интервью**, идти к шагу 2. Источник «текст» → режим **RFC**: шаг 2 пропущен (бриф = чужой прогон анкеты), идти к шагу 3.

**Шаг 2 — анкета** *(только режим интервью)*. Проектировщик задаёт владельцу 6 вопросов (таблица А) по порядку. Каждый ответ → строка протокола (формат Б). «Предположи сам» → проектировщик формулирует кандидата с числом вслух; статус строки — предположение. Финал — пересказ-чекпоинт; каждое расхождение → новая строка протокола. Результат: бриф-черновик (текст) для шага 3.

**Шаг 3 — детекторы** *(работа с текстом)*. Проектировщик сканирует текст (принесён или получен на шаге 2): каждый **ярлык без числа** → строка протокола «сколько?»; каждое **число без владельца** → строка «кто установил, с какой точностью?». Результат: все явные маркеры текста имеют строки.

**Шаг 4 — щупы** *(работа с молчанием)*. Проектировщик строит перечень **целей**: поля рамки 1–5 + сущности домена (В). К каждой цели применяет **щупы** (Г); тема не покрыта ни текстом, ни готовыми строками → новая строка протокола. Результат: все молчания вскрыты.

**Шаг 5 — кандидаты и судьбы** *(по каждой строке)*:
- 5.1 `ответ_кандидат`: владелец ответил → `владелец_ответил`; нет ответа, сорт технический → кандидат = порядок из справочника, `предположение`; сорт поведенческий → кандидат «по себе», `предположение`; не формулируется → `ждём_владельца`;
- 5.2 `куда_ляжет` — по раскладке (Д);
- 5.3 строка нерелевантна → `вычеркнуто`.

**Шаг 6 — раздача судеб:**
- `владелец_ответил` / `предположение` → значение в назначенное поле рамки (запись — владелец; для предположений проектировщик во временном кресле, с пометкой);
- `ждём_владельца` → строка копируется в реестр вопросов и уходит наружу;
- `вычеркнуто` → остаётся в протоколе для истории.

**Шаг 7 — проверка завершения.** Есть строки без судьбы → шаг 5. В рамке живой ярлык, число без владельца/пометки, НФТ без числа → шаг 4 (непокрытая цель) или к владельцу (уточнение/торг). Оба пункта чисты → **этап завершён**.

**Повторный запуск (до-заполнение).** Вход — строка реестра вопросов с пришедшим ответом; шаги 5–7 только для неё; вычислимые числа рамки пересчитываются сами.

## Материалы шагов

**А. Анкета (шаг 2):**

| № | Вопрос | Что закрывает |
|---|---|---|
| 1 | «что именно?» — сужение продукта: имя продукта — не задача | границы продукта |
| 2 | «кто пользователи и что делают?» — акторы и главный сценарий | поле 2 (ФТ) |
| 3 | «какой масштаб?» — аудитория, действий/день, география | поля 1 и 4 |
| 4 | «что делаем в v1 / чего не делаем?» — оба знака ФТ | поле 2 (ФТ) |
| 5 | «какие ожидания по качеству?» — число для каждой надежды | поле 3 (НФТ) |
| 6 | «какие ограничения?» — бюджет, команда, срок | поле 5 |

**Б. Строка протокола опроса (шаги 2–6):**

```yaml
строка_опроса:
  вопрос:          # формулировка
  ответ_кандидат:  # число / поведение / граница; может быть пустым, пока нет
  статус:          # ждём_владельца | предположение | владелец_ответил | вычислимо | вычеркнуто
  куда_ляжет:      # поле2_делаем | поле2_не_делаем | поле3 | поле4 | реестр_вопросов
```

Инвариант: каждая строка заканчивается — в рамке, в реестре вопросов или вычеркнутой (проверяет шаг 7). Подробный пример заполнения протокола (домен «прокат самокатов», 14 строк, все судьбы, выход в рамку и реестр) — [[Пример заполнения протокола опроса]].

**В. Цели щупов (шаг 4):** слой полей — поля 1–5, одинаков для любого домена; слой сущностей домена — перечень приносит проектировщик; готовая колода целей по типам приложений — [[Уточняющие вопросы по типам приложений]].

**Г. Щупы:** «сколько?» · «как часто? когда хуже всего?» · «что произойдёт, если …откажет / офлайн / ×2?» · «кто это установил?» · «надолго?» · «где?» · «чего мы не делаем?»

**Д. Раскладка (шаг 5.2):**

| Сорт ответа | Пример | Куда |
|---|---|---|
| число-обещание | «p95 ≤ 300 мс» | поле 3 (НФТ) |
| число-условие | «друзей в среднем 5»; «телеметрия раз в 5 с» | поле 4 (параметры нагрузки) |
| поведение | «что происходит, если получатель офлайн?» | поле 2 «делаем» |
| граница | «поиск по истории — нет» | поле 2 «не делаем» |

Тест для чисел: обещание системы или условие мира?

## Форма вопроса

Вопрос-поведение, не вопрос-решение («что произойдёт, если…», а не «как мы будем…»); маркер — названная часть системы внутри вопроса; та же стерильность, что у записей рамки.

## Типичные провалы

- сбор только по слою полей — «учётка и оплата» для любого домена (доменный слой пропущен);
- стоп-куча: строки без судеб, протокол стал свалкой (нарушен инвариант Б);
- кандидат «из головы» — без справочника и без владельца (нарушено правило двух источников);
- вопрос-решение вместо вопроса-поведения;
- ярлык пережил этап живым — не стал ни числом, ни «не делаем»;
- на анкете — молчаливое угадывание вместо предположения вслух.
