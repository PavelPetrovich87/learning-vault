# П3 «Бюджет latency» — подалгоритм шага 2

> Подалгоритм шага 2 [[шаг-2-бюджеты-ролей]] · обзор конвейера: [[шаг-2-конвейер.drawio]] · термины: [[словарь]] · диаграмма: [[п3-бюджет-latency.drawio]]

**Назначение.** Делит SLO latency (p95 ≤ X) на доли ролей: `SLO = доставка + Σ фаз ролей`.

**Вход (откуда).**

- SLO latency + сценарии, при которых оно обещано (поле 3 · поле 6).
- Справочник: доставка по условию (регион ~десятки мс, межрегион ~сотня), порядки цен фаз.
- Пути из П2.

**Алгоритм.**

1. Вычесть доставку (среда до входа системы и обратно — не роль, в составе её нет): остаток доступен ролям.
2. Суммировать цены фаз по пути — порядки справочника, не бренды; порядка нет → строка в реестр вопросов.
3. Сверка сверху в каждом сценарии обещания: доставка + Σ фаз ≤ SLO? Пик — запросов больше, очереди длиннее; рост — данных больше, чтение дольше.
4. Не влезает даже из минимумов → по возрастанию цены: перераспределить → сменить состав (возврат на шаг 1) → торг с владельцем.
5. Дележ: влезает — остаток самой дорогой фазе (единственная правка чисел без смены состава); сборка обратно обязана сойтись: 100 + 10 + 390 = 500 ✓.

**Выход (куда).** `бюджеты_ролей` latency (роль · требуемое · выведено_из: SLO · сценарий) и `доставка` (вычет, не бюджет роли); исключения — реестр вопросов, возвраты.

**Типичные провалы.**

- Идеальный путь: чистое обслуживание без очередей и доставки.
- Бюджет из воздуха: число не выводится из SLO — происхождение обязательно.
- Молчаливая правка SLO: не влезает — и число рамки тихо поправили под расчёт.
