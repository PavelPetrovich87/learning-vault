# П2 «Нагрузка на роли» — подалгоритм шага 2

> Подалгоритм шага 2 [[шаг-2-бюджеты-ролей]] · обзор конвейера: [[шаг-2-конвейер.drawio]] · термины: [[словарь]] · диаграмма: [[п2-нагрузка-на-роли.drawio]]

**Назначение.** Превращает параметры нагрузки рамки в λ на каждую роль — исполняет формулу «нагрузка на роли = параметры нагрузки × механика взаимодействия».

**Вход (откуда).**

- Поле 4 «Параметры нагрузки»: DAU · действий/день · пик ×3 + подраздел «нагрузка по действиям» (действие · доля · объект).
- Состав (модель, шаг 1) — связи, по которым идёт проводка.
- Сценарии (поле 6): день · пик · рост.
- Механика взаимодействия — наше решение (модель): поллинг против push, обращений на действие.

**Алгоритм.**

1. Проводка: каждое действие (глагол ФТ «делаем») от входа системы (роль без входящих связей; клиент — не роль) по цепочке ролей — получается путь.
2. Механика решает, сколько запросов порождает действие на каждом участке пути («одно действие ≈ один запрос» — тоже механика, а не закон).
3. λ на роль в сценарии = DAU × действий/день ÷ 86 400 × пик-множитель × доля действия × запросов/действие. Пример: 50 000 × 10 ÷ 86 400 ≈ 5.8/с; пик ×3 ≈ 18/с; поиск 40% → ≈ 7/с.
4. Путь — рабочий материал: рождается и выбрасывается; в модель пишется только свёртка.

**Выход (куда).** `нагрузка_на_роли` (роль · сценарий · λ запр/с) — в производные модели; пути — в память прогона: их читают П3 (Σ фаз по ролям пути) и П5 (W = фазы + ожидания).

**Типичные провалы.**

- Один сценарий: посчитали «день», забыли пик и рост.
- Идеальный путь без механики: «слушание» поллинга не посчитано.
- Писать пути в модель — мусор; в модели только свёртка.
