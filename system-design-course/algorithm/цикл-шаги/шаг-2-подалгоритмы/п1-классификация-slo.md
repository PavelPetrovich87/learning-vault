# П1 «Классификация SLO» — подалгоритм шага 2

> Подалгоритм шага 2 [[шаг-2-бюджеты-ролей]] · обзор конвейера: [[шаг-2-конвейер.drawio]] · термины: [[словарь]] · диаграмма: [[п1-классификация-slo.drawio]]

**Назначение.** Диспетчер шага 2: каждое SLO рамки прогоняется через тест делимости и маршрутизируется — делимое уходит в свой бюджет-подалгоритм (latency → П3, доступность (availability) → П4), неделимое подтверждается у носителя из протокола покрытия. Стоимость получает вердикт «не режем».

**Вход (откуда).**

- SLO — все НФТ-числа рамки (поле 3): требуемое значение + условие (сценарии обещания).
- Протокол проверок состава (модель, шаг 1): покрытие «требование → носитель».

**Алгоритм.**

1. Выписать все SLO — ни одно не теряется, включая «неудобные».
2. Тест делимости к каждому: можно ли назначить ролям доли, собирающиеся обратно в общее число?
   - latency — сумма времён ролей пути → делимое → П3;
   - доступность — произведение доступностей ролей пути → делимое → П4;
   - сохранность — нет сборки → неделимое → носитель;
   - стоимость — сумма, но не режем: валюта кандидатов шагов 4–5.
3. Неделимое → носитель из протокола; шаг 2 подтверждает, нового носителя не ищет. Нет носителя — возврат на шаг 1 (дыра в составе).
4. По одному качеству за раз: мс, девятки и рубли не смешиваются.

**Выход (куда).** Маршрут требований (какое SLO в каком подалгоритме); запись `неделимые` (требование · носитель) в пакет выхода шага; сигнал возврата на шаг 1.

**Типичные провалы.**

- Делить неделимое: «хранилище теряет не больше 40% объявлений» — абсурд.
- Резать стоимость раньше шагов 4–5.
- Потерянное SLO: диспетчер обязан выписать все.
