# 🧠 Topic: dependency-cruiser — принудимый граф зависимостей для JS/ESM

> [!abstract] Executive Summary (ELI5)
> Инструмент строит граф «кто кого импортирует» (умеет алиасы webpack/vite, .vue, ESM+CommonJS) и прогоняет каждое ребро через список запретов-регэкспов. Правила — **не плагины, а данные**: пара строк в конфиге. Легаси-нарушения не чинятся, а замораживаются в baseline — причём на уровне *ребра*, так что новый нелегальный импорт даже в старом грязном файле красит гейт. Это «золотые скриншоты, только для архитектуры»: ввёл правило без единой правки кода, дальше — только вычёркивать.

---

## 🎯 The "Why"

**Проблема:** архитектурные конвенции («HTTP только через обёртку», «модели не знают о вьюхах», «не трогать мёртвый вендор») живут текстом в README/AGENTS.md — то есть исполняются *дисциплиной*. Дисциплина протекает: ESLint `no-restricted-imports` видит только прямые импорты (нет транзитивности и слоёв), `eslint-plugin-import` хрупок на алиасной семантике, madge стагнирует. dependency-cruiser — единственный живой движок принудимых правил на графе зависимостей для JS/ESM.

**Для агентной разработки — вдвойне:**
- граф = машина инвариантов behavior-preserving рефакторинга (графовый дифф «изменилось ровно задуманное»);
- правила, исполняемые инструментом, агент не может «не заметить» — см. мета-принцип из [[Database-Drift-Prevention]] (E2): чем ниже уровень энфорсмента, тем меньше сломаешь;
- JSON-экспорт графа — бесплатный артефакт для субагентов (срезы импортеров, fan-in/fan-out).

---

## 💡 Mental Model & Analogy

**Таможня на границах слоёв.** Каждый импорт — пересечение границы; таможенник (движок) сверяет ребро со списком запретов. Легаси-карго, ехавшее до открытия границы, получает «разрешение на провоз» (запись в baseline), но новые попытки провоза того же запрещённого груза — красные. Альтернативная метафора: golden screenshots для архитектуры — baseline коммитится, дифф ревьюится, файл машинонезависим (пути + правило, без пикселей).

## 📚 Каталог фактов и техник

### A. Модель правил: данные, не плагины

**A1. Правило = декларация.** `forbidden: [{ name, severity, from: {path}, to: {path} }]` — регэкспы по **резолвнутым** путям (не по спекификаторам!), поэтому относительные импорты ловятся наравне с алиасными. Плагинов правил не существует — движок один, ecosystem-зависимости нет.

**A2. Словарь матчей задаёт движок.** Кроме `path`/`pathNot`: атрибуты ребра и модуля — `couldNotResolve`, `circular`, `orphan`, `dependencyTypes`, `reachable`/`reaches`. Пример: запрет циклов — это `to: {circular: true}`, тоже пара строк.

**A3. Готовые заготовки — в шаблоне `--init` и доке rules-reference.** Это «поваренная книга» (копируй-адаптируй), не пакеты. Специфичные конвенции проекта («HTTP только через API.js») никто за тебя не напишет — в этом и ценность самописных правил.

### B. Резолюция и алиасы

**B1. Алиасы — один источник, несколько потребителей.** Вынести карту алиасов в общий модуль (`aliases.cjs`): бандлер импортирует, depcruise делает `require`. Дубль карты = молчаливый разъезд резолверов (ложные красные/зелёные). CJS-нюанс: из CJS в ESM пробрасывается только default-экспорт.

**B2. Ловушка v18+: `webpackConfig` — только `{fileName}`.** Инлайн-объект `{resolve: {alias}}` из ранних версий больше не принимается (schema `additionalProperties: false`). Решение — шим-файл на 5 строк (`module.exports = {resolve: {alias: require('./src/aliases.cjs')}}`): depcruise динамически импортит файл и выкусывает `.resolve`. Сам webpack не нужен — внутри бандлится enhanced-resolve.

**B3. Инвариант резолва ДО всего остального.** Кривые алиасы маскируются под «всё разрешено». Первым шагом — битый спекификатор в отчёте обязан появиться, полный скан обязан дать 0 unresolved, и только потом генерация baseline (иначе заморозишь unresolved-мусор).

### C. Ловушка couldNotResolve

**C1. Битый импорт без правила = зелёный гейт.** Неразрешённый импорт не падает, а помечает ребро атрибутом `couldNotResolve: true` и спокойно проходит дальше: `valid: true`. Краснеет только то, что подошло под правило `forbidden` — а слойные правила матчат резолвнутые пути, которых у неразрешённого ребра нет. Голый `'lib/vue'` НЕ ловится правилом «app → src/lib» принципиально, как ни переписывай регэксп.

**C2. Лечение — `not-to-unresolved`** (`to: {couldNotResolve: true}` — матч на атрибут, из шаблона `--init`): опечатка, битый алиас, удалённый файл → красный. Правило стартует пустым → любой будущий unresolved = новая запись, не в baseline → красный по ratchet-механике.

### D. Baseline-ratchet

**D1. Ratchet на уровне РЕБРА.** Запись = правило + from + to (резолвнутые пути). Тоньше file-level ignore: новый нелегальный импорт в уже замороженном файле → красный. Файл (`.dependency-cruiser-known-violations.json`) — плоский массив `{from, to, rule}`.

**D2. Дисциплина (как со скриншотами).** Перегенерация `--baseline` — осознанно и **отдельным коммитом** (смешанный коммит спрячет случайные новые нарушения); вычеркнуть запись = коммит фикса; **unresolved никогда не замораживать**; устаревшие записи безвредны, чистить перегенерацией на milestone'ах.

**D3. Жизнь при миграции структуры.** Замороженные рёбра не зависят от переездов соседей — смешанное состояние (половина старой структуры, половина новая) гейт держит без изменений; при финальном переходе — одна осознанная перегенерация.

### E. CLI-грабли

**E1.** Вывод в файл — `-f/--output-to`, **не** `-o`. **E2.** `--baseline [file]` жадно съедает следующую позицию → писать `depcruise src --baseline -c config` (позиционный первым). **E3.** Exit 1 при violations — не оборачивать в пайп без pipefail при проверке кода выхода. **E4.** `doNotFollow: node_modules` — первый хоп к пакета виден (запрет «импортировать vue-resource» работает), глубже не идём.

### F. Слепые зоны (важно!)

Статический граф не видит динамику: EventBus, глобальные регистрации компонентов, `Vue.use()`, jQuery-плагины, обращение по строковым именам в шаблонах/конфигах. Удаление кода по графу/orphan-детектору всегда + grep по строковым вхождениям.

### G. Приёмка гейта инжектами

Каждое правило доказывается инжектом: добавил запрещённый импорт → красный с именем правила → откатил → зелёный. Фирменный инжект для baseline: **вычеркнуть запись и получить красное легаси-ребро** — доказывает, что подавление реально применяется, а не декорация.

## ✅ Чек-лист (внедрить на новом проекте)

- [ ] `npm i -D dependency-cruiser` (точный пин), прогнать по всему src
- [ ] Алиасы — один общий файл: бандлер + depcruise (+ всё, что ещё резолвит)
- [ ] v18+: `webpackConfig: {fileName}` + шим-файл с `require` алиасов
- [ ] `not-to-unresolved` включён ДО генерации baseline
- [ ] Инвариант «0 unresolved» на полном скане подтверждён
- [ ] Правила матчат резолвнутые пути (`^src/...`), не спекификаторы
- [ ] Слои: от уровня проекта (models/services не знают о views — и т.п.)
- [ ] Baseline — отдельным коммитом; вычерк записи = коммит фикса
- [ ] Отдельный npm-скрипт (`lint:arch`) и отдельный шаг гейта (не вплетать в eslint — падение растворится)
- [ ] Инжект-набор: каждое правило + вычерк из baseline + битый спекификатор
- [ ] JSON-отчёт сохраняется как будущий граф-артефакт (`-T json`)
