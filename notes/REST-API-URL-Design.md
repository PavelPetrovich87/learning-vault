# 🧠 Topic: Дизайн URL и API-контракт (REST: версии, фильтры, пагинация, ошибки)

> [!abstract] Executive Summary (ELI5)
> URL API — это не «путь к файлу», а интерфейс программы, и у интерфейса должен быть номер редакции. Три решения, закрывающие 90% боли: **(1)** `/v1` в пути с первого дня — бесплатная страховка от будущих ломающих изменений; **(2)** фильтрация — плоская (`filter[поле]=значение`), без языка запросов, неизвестное поле → 400, а не молчаливое игнорирование; **(3)** ошибки — единый бланк RFC 7807 problem+json, рендерящийся ровно в одном месте (глобальный фильтр). Всё это enforcement инструментами: zod `.strict()`, whitelist-мапа сортировки, кодогенерация клиента из OpenAPI (сломал контракт — фронт не собрался).

---

## 🎯 The "Why"

**Проблема:** без зафиксированного контракта каждый эндпоинт (и каждый агент!) изобретает свой диалект. Музей анти-примеров — легаси eloomi5.32, всё видено лично:

- «ошибка» = `redirect('https://eloomi.com')` (тенант не резолвился);
- «нет прав» = `dd("Permission denied!")` посреди контроллера;
- «компания не существует» = HTML-страница `"Sorry, this company does not exist."`;
- 500 при `APP_DEBUG=true` показывала клиенту **текст SQL и стек** (`SQLSTATE ... (SQL: SELECT distinct(function) FROM users)` прямо в браузере).

Следствия: фронт не может ветвиться на текстах ошибок (нужен машиночитаемый `code`), i18n невозможен (сервер прислал готовую английскую строку), логи — свалка (нет correlation-ID), а агент молча игнорирует опечатку в фильтре и строит выводы на слишком широкой выборке.

---

## 💡 Mental Model & Analogy

- **Контракт = стандарт розетки.** Вилку (клиента) можно менять как угодно, пока держится стандарт (версия). Изменить «распиновку» = выпустить новый стандарт (v2), а не тихо переточить старый.
- **Ошибка = внутренний документ; фильтр = погранпереход.** Доменная ошибка живёт на внутреннем языке (`organization.unit.cycle_detected`), наружу через HTTP проходит один перевалочный пункт (ProblemFilter), перекладывающий её в международный бланк problem+json.
- **Приложение = завод с несколькими проходными.** HTTP — главный вход (клиент ждёт ответа); очередь BullMQ — грузовой въезд (клиента нет, отвечать некому → только лог); события/cron — свои двери. Рендер ошибки определяется тем, **откуда пришла работа**, а не тем, где ошибка родилась.

## 📚 Каталог решений

### A. Версионирование: `/api/v1/...` с первого дня

Ломающее изменение (breaking) — любое, после которого клиент под старый контракт перестаёт работать: удалить/переименовать поле, сменить тип, сделать опциональное обязательным, изменить семантику. Аддитивное — безопасное: новое опциональное поле, новый эндпоинт.

Почему `/v1` сразу: версионирование дёшево **до** того как нужно (5 символов в роутах) и дорого **после** — ввод версий в существующий API сам является breaking change (старые клиенты ходят по старым путям). Внутри версии — только аддитивные изменения; ломающее → `/v2` (механика отложена, принцип зафиксирован). Коварный случай: добавление значения в enum формально аддитивно, но валит клиентский `switch` без `default`.

### B. Пути

`/api/v1/<context>/<resource>` — контекст в пути продолжает физическую топологию (PG-неймспейсы из ADR-006): `/api/v1/organization/units`, `/api/v1/learning/courses`. Ресурсы — во множественном числе, kebab-case.

### C. Фильтрация, сортировка, пагинация

Спектр подходов (от простого к языковому):

| Школа | Пример | Фильтры | Сортировка | Пагинация |
|---|---|---|---|---|
| GitHub REST | `?state=closed&assignee=x` | плоские | `sort` + `direction` | offset |
| JSON:API | `?filter[status]=draft` | `filter[...]` | `sort=-createdAt,name` | `page[number]` |
| Stripe | `?created[gte]=148...` | плоские + операторы у дат | — | курсор `starting_after` |
| OData | `$filter=Status eq 'Draft'` | язык запросов | `$orderby=... desc` | `$top/$skip` |
| GraphQL | аргументы схемы | типизированные | `orderBy: {field,direction}` | курсор `first/after` |

**Наш выбор** (критерии: греппабельность, тривиальная кодогенерация, агенто-устойчивость):
- `filter[<поле>]=<значение>`; повтор параметра = IN (`filter[status]=draft&filter[status]=published`);
- диапазоны — суффиксные поля `filter[createdAtFrom]`/`[createdAtTo]` (а не `[createdAt][gte]` — плоско и греппабельно);
- поля = camelCase имена полей DTO, всё валидируется zod; **неизвестный фильтр → 400** (опечатка не должна молча расширять выборку — «лучше упасть, чем молча вернуть не то», родство с RLS-решением);
- `sort=-createdAt,name` (минус = desc, запятая = составная) + zod-whitelist полей на каждый эндпоинт (ORDER BY не параметризуется → имя колонки только через мапу, иначе SQL-инъекция);
- курсорная пагинация (keyset): стабильна и O(limit) в отличие от offset (дубли/пропуски при вставках, деградация `OFFSET 100000`); курсор **привязан к сортировке**, из которой построен; тай-брейкер `id` в конце orderBy — иначе страницы «пляшут»; `take: limit + 1` — детект следующей страницы;
- полнотекстовый поиск — отдельный параметр `q` (поисковый индекс ≠ фильтры равенства).

### D. Ошибки: RFC 7807 problem+json

Стандартный бланк: `type` (URI класса проблемы — машинный ключ), `title` (стабильная сводка класса), `status`, `detail` (динамика этого случая), `instance` (URL запроса); `Content-Type: application/problem+json`; **extension-поля легальны** — туда наши добавки:

```jsonc
{ "type": ".../problems/organization.unit.cycle_detected",
  "title": "Move would create a cycle", "status": 409,
  "detail": "Unit cannot be moved under its own descendant",
  "code": "organization.unit.cycle_detected",   // ← таксономия ADR-003, extension
  "instance": "/api/v1/organization/units/123/parent",
  "traceId": "6f9c…" }                           // ← correlation, extension
```

Правила связки с ADR-003:
- доменные ошибки (`NotFound`→404, `Conflict`→409, `InvalidValue`→400) ничего не знают про HTTP; статус живёт в фильтре (`httpStatusOf` по instanceof);
- `code` дублируется рядом с `type` сознательно: greppable-строка, одинаково ищется в коде, логах, ADR; `type` выводится из code механически;
- `title` — из статического реестра кодов (полнота реестра проверяется тестом), `detail` — динамика; в ответе **никогда** нет стека, SQL, путей файлов;
- валидация: `ZodError` → 400 + `errors: [{path, message}]` (path — dot-строка для биндинга на поля формы);
- `traceId`: UUIDv4 на запрос → AsyncLocalStorage → в каждый лог и в каждый problem-ответ; ретрофит дорог, с первого дня ~30 строк;
- 500 — тот же конверт, `platform.internal_error`, стек только в лог;
- **единственная точка рендера** — глобальный `ProblemFilter` (регистрация один раз в `main.ts`); контроллеры только бросают; grep-правило «нет ручного `res.status(4xx).json` в presentation»; e2e asserts форму ошибок;
- OpenAPI: problem-схема один раз, ошибочные ответы через `$ref` → кодогенерация даёт фронту **типизированные ошибки**;
- по дороге никто не ловит и не переупаковывает; легальный catch один — перевод инфра-ошибки в доменную на границе репозитория (Prisma P2002 → `EmailAlreadyTakenError`);
- не-HTTP входы (BullMQ-процессор, cron): того же `UnitCycleDetectedError` нет нужды рендерить в problem+json — там нет ждущего клиента; «фильтр очереди» = try/catch + лог + политика ретраев BullMQ.

### E. Конвейер запроса списка: валидатор → переводчик → исполнитель

```
строка URL ──① ВАЛИДАТОР──► проверенные данные ──② ПЕРЕВОДЧИК──► структуры Prisma ──③ ИСПОЛНИТЕЛЬ──► SQL
             ListUnitsQuery                     SORT_MAP + parseSort            findMany
```

- **① `ListUnitsQuery`** (zod, presentation): пограничник — «известно ли и корректно ли». Вход: сырой текст URL (в query-строке всё строки). Выход: типизированные значения (`sort: '-name'` — строка из enum). Значение `sort` — часть query-строки, zod его **проверяет**, но не переводит.
- **② `SORT_MAP`** (словарь query-сервиса): перевод публичного имени поля в колонку БД. Отдельно от zod, потому что: разные профессии (валидация ≠ перевод), разные слои (ADR-003: zod в presentation, перевод — кухня query-сервиса), и **безопасность** — lookup в мапе единственный путь от строки к имени колонки (`SORT_MAP['; DROP'] → undefined`), вторая линия обороны даже при ослабленном enum. Технически можно склеить через zod `.transform()` — сознательно не смешиваем.
- **③ `findMany`** (Prisma): исполнитель, потребляет выходы ① и ② — `where` собран из валидированных фильтров, `orderBy: [{ [column]: dir }, { id: dir }]` из переведённой сортировки; Prisma не интерполирует идентификаторы из строк — имена таблиц/колонок только из модели.

Рентген данных (как `'-name'` умирает на станции ②):
```
URL      ?sort=-name&filter[parentId]=0192f3e7...&cursor=eyJ...
① parse  { sort: '-name', 'filter[parentId]': '0192f3e7...', cursor: 'eyJ...' }
② перев. { dir:'desc', column:'name', keyset:{ name:'Sales', id:'0192a...' } }
③ Prisma findMany({ where:{ parentId:'0192...', name:{lt:'Sales'} }, orderBy:[{name:'desc'},{id:'desc'}], take:21 })
SQL      SELECT ... WHERE parent_id=$1 AND name<'Sales' ORDER BY name DESC, id DESC LIMIT 21
```

## ✅ Чек-лист (внедрить на новом проекте)

- [ ] `/v1` в путях с первого дня; политика «внутри версии только аддитивное» — в ADR
- [ ] Пути `/api/v1/<context>/<resource>`, множественное число, kebab-case
- [ ] zod `.strict()` на query → неизвестный фильтр/сортировка = 400, не молчание
- [ ] Whitelist-мапа полей сортировки (DTO-имя → колонка); прямой подстановки строк в ORDER BY нет
- [ ] Курсорная пагинация + тай-брейкер `id`; `take: limit+1`; смена сортировки сбрасывает курсор
- [ ] Единый бланк ошибок problem+json; `code`-extension из доменной таксономии; реестр titles + тест полноты
- [ ] Глобальный ProblemFilter один; grep-правило против ручного форматирования ошибок
- [ ] ZodError → 400 + `errors[{path,message}]` (dot-строки)
- [ ] traceId (v4): middleware → AsyncLocalStorage → в логи и в ответы
- [ ] 500 без стека/SQL/путей; стек только в лог
- [ ] Problem-схема в OpenAPI через `$ref` → типизированные ошибки на фронте
- [ ] Очередь/события: свои «рендеры» (лог+ретраи), домен не знает про HTTP
- [ ] Кодогенерация клиента из спеки в CI/verify — breaking change роняет сборку фронта
