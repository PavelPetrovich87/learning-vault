# 🧠 Topic: OpenAPI из zod — контракт, который не врёт

> [!abstract] Executive Summary (ELI5)
> **OpenAPI** — машиночитаемый чертёж REST API: файл, где перечислено, какие есть эндпоинты, что они принимают, что отдают и какими ошибками отвечают. **Zod** — библиотека, где описание формы данных («name — непустая строка») одновременно даёт и тип TypeScript, и проверку в рантайме. Связка: чертёж API **генерируется** из zod-схем. Контракт рисуется сам из единственного описания формы — поэтому он физически не может разъехаться с тем, что бэк реально проверяет.

---

## 🎯 The "Why"

**Проблема:** форма одного запроса в классическом подходе описана **трижды** — DTO-тип, валидатор, спека API (yaml-файл или декораторы). Три копии правды = гарантированный дрейф: декоратор забыли обновить → спека врёт → фронт по сгенерённым из спеки типам шлёт то, что бэк отвергает. Ошибка всплывает в рантайме, а не в компиляторе.

**Для агентной разработки критично вдвойне:** агент доверяет контракту как источнику истины; врущий контракт = систематические, а не случайные ошибки.

**Легаси-контраст:** в eloomi5.32 контрактом API был «код контроллера, попробуй догадайся» — спеки не было вовсе.

---

## 💡 Mental Model & Analogy

**Меню и карточка рецепта.** OpenAPI — меню ресторана: что можно заказать и что принесут. Zod — карточка рецепта на кухне. Классический подход: меню печатает дизайнер, готовит повар по своей памяти — меню врёт. Zod-first: **меню печатается прямо из карточки рецепта** — то, что на кухне реально готовят, и то, что написано в меню, — один документ.

## 📚 Разбор по слоям

### Что такое OpenAPI

Открытый стандарт (бывший Swagger) описания HTTP API в JSON/YAML. Ключевые части документа:

- `paths` — эндпоинты: `POST /organization/units`, параметры, тела, коды ответов;
- `components/schemas` — переиспользуемые структуры (`Unit`, `Problem`), на которые ссылаются через `$ref`;
- `operationId` — стабильное имя операции (`organization_createUnit`) — из него генерятся имена методов клиента.

Из спеки машина умеет делать: живую документацию (Swagger UI), **типизированного клиента** для фронта, моки (Prism), контракт-тесты.

Нюанс версий: **OpenAPI 3.1 построен на JSON Schema 2020-12** — поэтому zod-схема конвертируется в него почти 1:1 (честный `nullable`, без костылей старой 3.0).

### Что такое zod

```ts
export const UnitSchema = z.object({
  id: z.uuid(),
  name: z.string().min(1),
});

type Unit = z.infer<typeof UnitSchema>; // { id: string; name: string } — выведено

const unit = UnitSchema.parse(body);    // рантайм: невалидное тело → ZodError → 400
```

Двойная природа — ключ: схема это **объект в рантайме** (её можно конвертировать, сериализовать, передать в функцию), который *одновременно* служит источником компайлтайм-типа. Без неё TS-типы стираются при компиляции, и провалидировать пришедший по сети JSON нечем.

### Конвейер (шаги)

1. Разработчик пишет **одну** zod-схему DTO в presentation-слое.
2. Контроллер валидирует ей тело запроса в рантайме.
3. Registry эндпоинтов ссылается на те же схемы: `{ body: CreateUnitSchema, response: UnitSchema }`.
4. Задача `api:spec` обходит registry → `openapi.json` (генерат, руками не правится).
5. Генератор (`orval` / `openapi-typescript`) читает спеку → типизированный клиент в `packages/shared`.
6. Фронт получает типы, **гарантированно совпадающие** с валидацией бэка — одна схема в одном файле.

### Почему НЕ @nestjs/swagger

Декораторы `@ApiProperty()` означают: форма описана декоратором (для спеки) и отдельно валидатором (для рантайма). Двойное описание — тот же класс болезни, что «одна большая БД с сервисными классами» ([[Database-Drift-Prevention]]): копии правды расходятся молча.

## ✅ Механики, которые стоит перенять

- **`$ref` на общие схемы:** `Problem` (ошибки), envelope пагинации, параметры `cursor/limit` описаны **один раз** в shared и переиспользуются всеми эндпоинтами.
- **`operationId` — стабильный контракт:** переименование внутри версии = ломающее изменение; имена методов клиента генерятся из него.
- **`example` обязателен** в схемах тел: едут в документацию и моки; схема без примера не проходит ревью.
- **Спека не коммитится** — воспроизводимый генерат из кода (тот же принцип, что Prisma-клиенты в ADR-006): чистые диффы, невозможность «поправить json руками».
- **Контракт-тесты:** e2e-кейс «ошибка 400/404/500 соответствует problem-схеме из спеки» держит конверт честным.
