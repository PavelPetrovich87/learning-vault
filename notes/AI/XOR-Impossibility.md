# Почему XOR невозможен для одного перцептрона

Related: [[Perceptron-Basics]] · [[Hidden-Layer-New-Coordinates]]

> [!summary] TL;DR
> XOR требует, чтобы каждый вход в одиночку умел «включать» ответ, но вдвоём они включать не должны. Для прямой «сильный по одиночке ⇒ сильные в паре» — всегда. Отсюда противоречие в четырёх неравенствах: такой линии не существует, и никакой алгоритм обучения не поможет.

## 1. Точки те же, ответы другие

У AND и XOR один и тот же квадрат из четырёх углов, отличается только колонка правильных ответов:

| точка | AND | XOR |
|-------|-----|-----|
| (0,0) | 0 | 0 |
| (0,1) | 0 | **1** |
| (1,0) | 0 | **1** |
| (1,1) | 1 | 0 |

AND — «1, когда оба» (`a && b`); XOR — «1, когда входы **разные**» (`a !== b`). У XOR единицы стоят **по диагонали**: (0,1) и (1,0). Нули — на другой диагонали.

## 2. Доказательство в четыре неравенства

Предположим, существуют `w1, w2, b`, при которых `predict` отвечает правильно на все четыре точки. Каждое требование — просто «подставь точку в total и потребуй нужный знак»:

1. `(0,0) → 0`: total = **b** (веса умножились на нули) → нужно `b < 0`.
2. `(1,0) → 1`: total = **w1 + b** → нужно `w1 ≥ −b`.
3. `(0,1) → 1`: total = **w2 + b** → нужно `w2 ≥ −b`.
4. `(1,1) → 0`: total = **w1 + w2 + b** → нужно `w1 + w2 + b < 0`.

Складываем 2 и 3: `w1 + w2 ≥ −2b`, значит `w1 + w2 + b ≥ −b`. Требование 1 говорит `b < 0`, поэтому `−b > 0`, итого `w1 + w2 + b > 0`. А требование 4 настаивает, что эта же сумма **отрицательная**. Противоречие — при любых трёх числах.

Проверка «а если выкрутиться»: взять `b = −1`? Тогда пп. 2–3 задерут планку `w1, w2 ≥ 1`, и в (1,1) выйдет `1 + 1 − 1 = +1` — разрыв только растёт. Взять веса меньше? Сломаются пп. 2–3.

> [!important] Суть одной фразой
> **Каждый вход по одиночке должен быть сильнее bias (пп. 2–3), но вдвоём — слабее bias (п. 4).** Для прямой «сильный по одиночке ⇒ сильные в паре» выполняется всегда. Противоречие — в самой геометрии, не в алгоритме.

## 3. Почему геометрически: диагональ против диагонали

Линия умеет отделять «кусок от остального»: AND — один угол против трёх; OR — три против одного. У XOR классы **перемешаны по кругу**: идёшь по углам квадрата — ответы чередуются `0 → 1 → 1 → 0`. Отделить диагональ от диагонали нельзя: любые две точки, лежащие по одну сторону от какой-то прямой, тянут за собой... точнее, прямая, удерживающая обе диагональные единицы строго по одну сторону, неизбежно затаскивает туда один из нулевых углов. Диагонали крест-накрест пересекаются в центре квадрата — «щели» между ними нет.

## 4. Что при этом делает train: гонки по кругу

Обучающий цикл честно работает: исправляет ошибку в одной точке — и это **молча ломает другую**. В реальной трассе после пары хаотичных эпох веса зацикливаются намертво — одни и те же четыре исправления повторяются вечно:

```text
[0,0]: ошибка −1 → bias → −0.1            # затихомирили [0,0]
[0,1]: ошибка +1 → веса → [−0.1, 0.1], b → 0   # ...и разбудили [0,1]
[1,0]: ошибка +1 → веса → [0, 0.1], b → +0.1   # ...и разбудили [1,0]
[1,1]: ошибка −1 → веса → [−0.1, 0], b → 0     # ...вернулись к началу
```

Решения не существует — кружение не кончится никогда.

## 5. Историческая ремарка

Это ровно та стена, о которую перцептроны разбились в 1969: Минский и Пейперт показали невозможность XOR в книге *Perceptrons*, после чего финансирование нейросетей подсохло на десятилетие («AI winter»). Выход — **несколько** перцептронов: скрытый слой меняет координаты так, что простая прямая снова работает → [[Hidden-Layer-New-Coordinates]].
