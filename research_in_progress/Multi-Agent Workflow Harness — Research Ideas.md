# Multi-Agent Workflow Harness — Research Ideas

## Глобальное исследование

**Источник:** Анализ статьи Anthropic про динамические воркфлоу (Dynamic Workflows) в Claude Code. Файл: [[Claude_Code_Dynamic_Workflows_Анализ]]
**Цель:** Извлечь 6 паттернов и адаптировать их в универсальный инструмент разработчика, работающий в любой среде.

---

## Три проблемы стандартного одноагентного подхода

| Проблема | Суть | Последствия |
|----------|------|-------------|
| **Агентская лень** | В одном длинном контексте модель "сжимает" приоритеты, пропускает пункты | Пропуск критических проверок (безопасность, compliance) |
| **Предвзятость к своим результатам** | Модель склонна оценивать свою работу выше, чем чужую | Confirmation bias при ревью кода, data leakage в ML-моделях |
| **Смещение цели** | При компакции контекста теряются нюансы, ограничения, граничные условия | Результат "хороший", но не соответствует исходным требованиям |

**Вывод:** Все три проблемы архитектурные — они не лечатся "лучшим промптом", только изоляцией контекстов и разделением ролей.

## Шесть паттернов динамических воркфлоу

### 1. Classify-and-Act (Классифицируй и действуй)
Агент-классификатор определяет тип входных данных и маршрутизирует задачу специализированному агенту. Классификация — простая задача с высокой точностью, выполнение — узкая специализация.

**Применение:** роутинг тикетов поддержки, триаж медицинских симптомов, выбор модели под задачу (Haiku/Sonnet/Opus), категоризация инцидентов.

**Пример:** 50 000 обращений в чат поддержки оператора мобильной связи → классификатор направляет технические проблемы агенту-диагносту, запросы на отключение — human-агенту с приоритетом retention.

---

### 2. Fan-out-and-Synthesize (Разветви и синтезируй)
Большая задача декомпозируется на независимые подзадачи, каждая обрабатывается отдельным субагентом в изолированном контексте. Результаты синтезируются барьерной синхронизацией.

**Применение:** due diligence по 340 договорам, аудит 12 микросервисов, проверка ценообразования на 50 000 SKU, анализ больших наборов данных по частям.

**Ключевое преимущество:** предотвращает cross-contamination — рассуждения по одной задаче не искажают подход к другой.

---

### 3. Adversarial Verification (Состязательная верификация)
Для каждого агента-генератора запускается парный агент-верификатор, который состязательно проверяет вывод по рубрике. Верификатор не знает о рассуждениях генератора — он видит только результат.

**Применение:** ревью кода, проверка фактов в журналистике, верификация медицинских диагнозов, валидация финансовых моделей, regulatory compliance.

**Пример:** Фармацевтическое досье 2000+ страниц для Росздравнадзора — генератор собирает разделы, верификатор с ролью "скептик" проверяет каждое утверждение, второй раунд — агент-рецензент в роли инспектора.

---

### 4. Generate-and-Filter (Сгенерируй и отфильтруй)
На первом этапе генерируется большое множество вариантов (без самоцензуры). На втором — фильтрация по рубрике, дедупликация, верификация.

**Применение:** нейминг продуктов, архитектурные решения, генерация гипотез, список тест-кейсов, подбор дизайна.

**Ключевое преимущество:** генерация и оценка — разные когнитивные процессы. Совмещение подавляет креативность.

**Пример:** 5 агентов-генераторов придумали 87 названий для бренда косметики → агент-фильтр проверил уникальность, произносимость, домены → агент-рубрикатор выбрал топ-5. Фокус-группа: 89% одобрение (против 34% при стандартном подходе).

---

### 5. Tournament (Турнир)
N агентов решают одну задачу разными подходами. Агент-судья сравнивает результаты попарно по рубрике, пока не определяется победитель.

**Применение:** выбор архитектурного решения, ранжирование кандидатов, оценка серьёзности багов, сортировка по качественным критериям.

**Ключевое преимущество:** сравнительное суждение ("A лучше B?") надёжнее абсолютного ("оцени A по шкале 1-10"). Даже при ошибке в одном матче правильный кандидат пробивается через другие.

**Пример:** 1200 резюме на Senior Backend → грубая фильтрация → турнирная сортировка 340 резюме попарно → топ-20 с обоснованием. Time-to-first-interview: 3 недели → 3 дня.

---

### 6. Loop until Done (Цикл до завершения)
Цикл агентов запускается до выполнения условия остановки, а не фиксированного числа итераций. Условие привязано к реальному состоянию системы.

**Применение:** поиск всех вхождений паттерна в кодовой базе, итеративный рефакторинг до прохождения тестов, дедупликация данных, расследование инцидентов.

**Пример:** Замена устаревшей библиотеки шифрования в 800 000 строк legacy-кода. Условие остановки: "3 итерации подряд без новых реальных использований". Найдено и заменено 147 реальных использований, отсеяно 1800+ false positives.

## Архитектурные мысли о Harness

### Набор агентов
- **Researcher** — сбор контекста, чтение кода, поиск по репо
- **Planner** — декомпозиция задачи, построение плана
- **Implementer** — написание кода по спеке
- **Reviewer** — ревью кода, поиск багов (Adversarial Verification)
- **Tester** — генерация и запуск тестов
- **Documenter** — обновление документации, README

### Скрипты-оркестраторы
- **Sequential Flow** — агенты по цепочке
- **Parallel Flow** — независимые агенты одновременно
- **Routing Flow** — Classify-and-Act
- **Evaluator-Optimizer** — цикл: сделал → проверил → переделал
- **Orchestrator-Workers** — главный агент декомпозирует и собирает
- **Aggregator** — сбор фрагментов в единый артефакт

## Когда НЕ использовать воркфлоу

| Сценарий | Почему не стоит |
|----------|----------------|
| Простые задачи (5 строк кода) | Накладные расходы превысят выгоду |
| Детерминированные операции (JSON → CSV) | Один правильный ответ, не нужны альтернативы |
| Ограниченный бюджет | Мультиагентность потребляет больше токенов |

## Главный вопрос: как встроить в жизнь разработчика?

### Спектр задач
- Начать новый проект / фичу
- Рефакторинг legacy-кода
- Code review внешнего PR
- Написание тестов на существующий код
- Документирование API
- Багфикс по тикету
- Deep research по технологии
- Миграция между фреймворками

### UX-идеи
- **CLI-команда** в любом репо: `harness start bugfix --ticket=PROJ-123`
- **GitHub Action / CI Integration** — автозапуск на PR
- **VS Code Extension** — панель с задачами, выбор флоу, прогресс
- **Pre-commit hook** — lightweight reviewer перед коммитом
- **Сохранение шаблонов** в `~/.config/harness/workflows` — библиотека из 5-10 проверенных воркфлоу
