# sleight-of-mouth — Agent Guidelines

Проект модульного представления книги **Р. Дилтс «Фокусы языка. Изменение убеждений с помощью НЛП»** (Robert Dilts, *Sleight of Mouth*, 1999; рус. изд. СПб.: Питер, 2010) и разработки на её основе библиотеки алгоритмов работы с убеждениями.

## О книге

Книга отвечает на вопрос: **как словами создаются, меняются и разрушаются убеждения**. Ядро — 14 вербальных паттернов («фокусов языка»), каждый из которых переупаковывает ограничивающее убеждение, не споря с человеком, а расширяя его «карту мира». Это операционная система там, где обычно бывают либо бесплодный спор, либо капитуляция перед «это же очевидно».

Структура (9 глав + приложение):

| Главы | Блок | Содержание |
|---|---|---|
| 1–4 | Концептуальный фундамент | карта ≠ территория; фреймы и рефрейминг; группирование (чанкинг); ценности, критерии, стратегии реальности |
| 5–6 | Теория убеждений | 3 типа ограничивающих убеждений (безнадёжность / беспомощность / никчёмность); структура: комплексный эквивалент («А = Б») и причинность («А → Б»); проверки соединительными словами; противоположные примеры |
| 7–8 | Процессы и патологии | 6-стадийный цикл изменения убеждений; внутренние состояния, якорение, сцепление; мысли-вирусы; нейро-логические уровни |
| 9 | Ядро системы | каталог 14 паттернов + ключевые вопросы-генераторы + система их применения |
| Прил. | Модель ROLE | чтение репрезентаций и состояний |

## Цель проекта (главная задача папки)

Представить книгу в виде **модулей**, где каждый модуль содержит **набор алгоритмов**. Дальнейшее развитие проекта — **модификация и композиция** этих алгоритмов под разные прикладные задачи (диалоговые сценарии, самопомощь, коучинг, защита от манипуляций).

Словарь проекта:

- **Модуль** — этап конвейера библиотеки: `00-states` (сквозной слой состояний) / `01-diagnosis` / `02-intervention` (внутри — пять семейств по мишеням) / `03-integration`. Зафиксировано 2026-08-29; происхождение алгоритма хранится в поле `source`, а не в структуре папок.
- **Алгоритм** — исполняемая процедура, извлечённая из книги (паттерн, упражнение, диагностический опросник, формат сессии), с обязательными **входом, выходом и шагами**.
- **Модификация** — адаптированная версия алгоритма (исходный книжный вариант сохраняется как `original`).
- **Композиция** — цепочка алгоритмов из разных модулей, собранная под конкретную задачу (сценарий).
- **Мишень** — место в структуре убеждения, по которому работает интервенция (5 шт.: основание / следствие / масштаб / рамка / мета); до диагностики — потенциальная, после — подтверждённая.
- **Уязвимость** — состояние мишени (потенциальная → подтверждённая → пересмотр после применения).
- **Семейство** — набор взаимозаменяемых алгоритмов под одну мишень.
- **Применение** — использование одного алгоритма по подтверждённой мишени с обязательной перепроверкой карты после.
- Регистр словаря — формальный; рабочие метафоры («кирпич», «гнездо», «удар», «слот», «разъём») упразднены. Полный словарь — `research/composition-model.md` §1.

## Источники (готовый материал)

- **Дистиллированная база знаний — внутри проекта:** [`knowledge/`](knowledge/README.md) (канон извлечённого материала). Состав: MD-файлы с YAML-frontmatter, `index.json`, корпус примеров `examples/corpus.jsonl` (50 пар «убеждение → ответ»). Весь материал книги уже извлечён: паттерны по карточкам, 25 упражнений, постраничные ссылки на издание 2010 г. (глоссарий RU↔EN вынесен на верхний уровень — `GLOSSARY.md`). Брать материал отсюда, не из PDF.
- **Слой синтеза (рядом с базой):** [`research/`](research/) — результат синтеза над базой, а не извлечённый материал: исследование классификаций `research/technique-classification.md`, закреплённая композиционная модель `research/composition-model.md` и диаграмма `research/assets/`.
- **Пайплайн пересборки из PDF и дом приложения:** `~/work/Dielts/` — исходный PDF, скрипт чистки `work/clean.py`, черновики глав `work/chapters/*.txt`, генератор диаграмм `diagrams/`, код приложения `app/` и инструменты `tools/`; контракт — `AGENTS.md` там. PDF используется только для сверки цитат и в волт не копируется (лицензия). Поток данных односторонний: волт → приложение через `tools/export.py` (разделение ответственности зафиксировано 2026-09-05 в AGENTS обеих папок).

## Опорные модели (выводы исследования, фундамент архитектуры)

1. **Двухслойность:** этапная классификация (диагностика → интервенция → интеграция) — ведущий сценарий сессии; классификация по мишени (5 классов: основание / следствие / уровень / рамка / рефлексия) — селектор внутри интервенции.
2. **14 паттернов = 6 глубинных механизмов** (сдвиг на цель, перекодирование словом, смена логического уровня, смена рамки, работа с обоснованием, рекурсия).
3. Паттерны двунаправленны (усиливают и ослабляют) — «направление» и «этика» не являются классификаторами; контроль применения задаётся композицией.
4. **Композиционная модель (закреплена 2026-08-29):** рабочая архитектура проекта — алгоритмы с контрактами вход/выход, четыре типа данных (фраза → карта → сдвиг → закреплено), пять мишеней в карте убеждения, группы взаимозаменяемых алгоритмов по мишени, серия применений с перепроверкой после каждого. Канон: [`research/composition-model.md`](research/composition-model.md), диаграмма — `research/assets/`. Новые материалы строятся в терминах этой модели; развитие — расширением в приближении (zoom-in) по мере прохождения книги, не пересборкой. Словарь модели зафиксирован (там же, §1).

## Структура папки

```
sleight-of-mouth/
├── AGENTS.md            ← этот файл
├── GLOSSARY.md          ← глоссарий терминов RU ↔ EN (пополняется по мере изучения модулей)
├── knowledge/           ← ГОТОВАЯ база знаний книги (уже существует; канон извлечённого)
├── research/            ← слой синтеза над базой (уже существует): классификации,
│                          закреплённая композиционная модель + диаграмма (assets/)
├── INDEX.md             ← карта алгоритмов (создаётся при первом наполнении модулей)
├── modules/             ← библиотека алгоритмов; ось — этапы (каркас создан 2026-08-29)
│   ├── AGENTS.md        ← контракт библиотеки: frontmatter, размещение, именование
│   ├── 00-states/       ← сквозной слой состояний
│   ├── 01-diagnosis/    ← фраза → карта
│   ├── 02-intervention/ ← карта → сдвиг; подпапки f1–f5 — семейства по мишеням
│   └── 03-integration/  ← сдвиг → закреплено
└── compositions/        ← сценарии компоновки алгоритмов под задачи
```

Frontmatter алгоритма (обязательные поля): `id`, `module`, `type: algorithm`, `input`, `output`, `source` (глава/страницы издания 2010), `status`, `version-kind: original | adapted | composed`, `created`/`updated`.

## Правила

1. **Каркас модулей создан 2026-08-29** (ось — этапы; решение пользователя, библиотека позиционируется как практический инструмент). Наполнение — по ходу изучения книги; размещение алгоритмов — по правилам `modules/AGENTS.md`.
2. Язык — русский (working zone); термины дублируются английскими, имена паттернов — `Название (En Name)`.
3. Алгоритм без `input`/`output` не принимается — входы/выходы являются контрактами композиции.
4. Исходный книжный вариант алгоритма не затирается модификациями; версии живут рядом и различаются `version-kind`.
5. Любой алгоритм ссылается на источник (глава/страницы) — трассируемость до книги обязательна.
6. Материал берётся из `knowledge/` этой папки (канон). При расхождениях база — источник истины, PDF (в `~/work/Dielts/`) — для сверки. Черновики пайплайна не редактируются.
7. Единственный источник правды — волт. Данные приложения (`app-data/`) и `INDEX.md` генерируются из волта односторонним экспортом (`~/work/Dielts/tools/export.py`) и руками не правятся; приложение не пишет в волт.
8. Глоссарий живёт на верхнем уровне (`GLOSSARY.md`) и пополняется по мере продвижения по книге: при изучении каждого следующего модуля обязательно выделять встреченные термины и вносить их туда — русский термин, английский эквивалент, глава/страницы. Глоссарий растёт вместе с работой, а не пишется один раз.
