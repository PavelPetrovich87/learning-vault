# Контракт «карта» — выход модуля

Центральный тип данных библиотеки. Машинное представление — [`map.yaml`](map.yaml); онтология полей и мишеней — канон [`composition-model.md`](../../../../research/composition-model.md) §4.

## Поля

- `фраза` — исходная формулировка, копия входа после проверок порта; вписывается при создании карты, до b1. Материал для [b2-detect](../../b2-detect/README.md) — маркеры уровня фразы, не звеньев (обесценивающее «но», соположение), — и для потребителя `02-intervention`: паттерны книги сформулированы как вербальные ответы на высказывание, а не на свёрнутые звенья.
- `тип` — CEq («А = Б»), C-E («А → Б») или `неполное` — обобщение без связки (норма полноты, гл. 6, с. 125). Полнота — проекция типа: `полное = тип ≠ неполное`, отдельного поля-флага нет. Меняет чтение мишеней I–II: для CEq звено — определение (I — переопределение термина, II — переоценка ценности), для C-E — причина и следствие буквально.
- `A` — основание: причина (C-E) или определяемый термин (CEq); при `неполное` — фрагмент-обобщение, до раскрытия в b3.
- `B` — следствие: результат (C-E) или определение (CEq); при `неполное` — пусто.
- `мишени I–V` — состояние уязвимости каждой мишени: `—` / `▲` / `▲▲`. Жизненный цикл уязвимости (канон §1): потенциальная → подтверждённая `▲` (после диагностики) → пересмотр после каждого применения.

## Наполнение блоками

Карта создаётся вместе с полем `фраза` (копия входа, решение 2026-09-05) и дальше заполняется блоками последовательно, промежуточных контрактов нет — состояния одного объекта:

1. [b1-parse](../../b1-parse/README.md) заполняет `тип, A, B`; при неполном — `тип = неполное`, фрагмент в A, B пусто;
2. [b2-detect](../../b2-detect/README.md) ставит отметки `мишени I–V` по маркерам во фразе;
3. [b3-explicate](../../b3-explicate/README.md) подтверждает (`▲` → `▲▲`) и раскрывает неполные формулировки — тип уточняется до CEq/C-E.

Предикаты `requires` / `fills` по полям карты — в README блоков.

## Результаты модуля

Выход модуля — `карта | отказ{причина}`. Карта — **артефакт**: данные, последовательно заполненные блоками. Отказ — **результат без артефакта**: не «невалидный вход», а итог работы модуля; причины — не утверждение (вопрос / императив), несколько утверждений в одной фразе (единица входа). В `map.yaml` отказа нет. Схема результатов разбора — [`b1-parse/outcomes.drawio`](../../b1-parse/outcomes.drawio).

## Потребитель

`02-intervention` берёт карту с подтверждённой мишенью (канон §5.2, применения идут серией с перепроверкой) — у себя заведёт входную ссылку на этот контракт.
