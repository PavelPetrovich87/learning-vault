# 01-diagnosis

Интерфейс: `фраза → карта убеждения | отказ{причина}` — отказ есть результат работы модуля, а не невалидный вход (причины: не утверждение, несколько утверждений). Контракты: [фраза](contracts/phrase/phrase.md) · [карта](contracts/map/map.md).

Блоки (внутренний порядок):
1. [b1-parse](b1-parse/README.md) — разбор: находит конструкцию CEq/C-E, заполняет поля `тип, A, B`; задаёт чтение мишеней I–II.
2. [b2-detect](b2-detect/README.md) — детекция: маркеры уязвимости во фразе → отметки мишеней I–V (кванторы общности → II, обесценивающее «но» → IV, монолитный ярлык → III…).
3. [b3-explicate](b3-explicate/README.md) — экспликация: вопросы-оси → подтверждение ▲/▲▲ и раскрытие неполных убеждений (4 вопроса-причины; «как ты узнаёшь…?»).

Промежуточных контрактов нет: блоки последовательно заполняют одну карту, стыки описаны предикатами `requires`/`fills` в README блоков.

Приёмка: основной выход алгоритма — заполнение или уточнение карты. Диагностический вопрос, работающий заодно как интервенция (№10 и подобные), остаётся здесь, если основной контракт диагностический; полный список этапов — `stage-fit`.
