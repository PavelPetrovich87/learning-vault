# modules/ — библиотека алгоритмов

Ось папок зафиксирована пользователем 2026-08-29: **этапная** (диагностика → интервенция → интеграция + сквозной слой состояний). Библиотека — практический инструмент сборки интервенций, а не пересказ книги: происхождение алгоритма хранится в поле `source`, а не в структуре папок.

## Дерево

```
modules/
├── AGENTS.md            ← этот контракт
├── 00-states/           сквозной слой состояний (обслуживает все этапы)
│                        порт слоя не определён (layer: state)
├── 01-diagnosis/        фраза → карта
│   ├── contracts/
│   │   ├── phrase/      вход: фраза (yaml + заметка + онтология drawio)
│   │   └── map/         выход: карта убеждения
│   ├── b1-parse/        блок «разбор»: → map [fills: тип, A, B]
│   ├── b2-detect/       блок «детекция»: map [requires: шапка] → [fills: мишени]
│   └── b3-explicate/    блок «экспликация»: map [requires: мишени] → выход модуля
├── 02-intervention/     карта → сдвиг; contracts/ при наполнении; пять семейств:
│   ├── f1-ground/       мишень I «основание»
│   ├── f2-consequence/  мишень II «следствие/ценность»
│   ├── f3-scale/        мишень III «масштаб»
│   ├── f4-frame/        мишень IV «рамка»
│   └── f5-meta/         мишень V «мета»
└── 03-integration/      сдвиг → закреплено; contracts/ при наполнении
```

## Правила размещения

1. **Наполнение — по ходу изучения книги** (zoom-in, принцип развития модели). Сейчас каркас пуст намеренно: ни один алгоритм не размещён.
2. Алгоритм кладётся в папку своего **основного этапа** — этап выводим из контракта вход→выход. Если алгоритм работает на нескольких этапах (№10 «стратегия реальности» — диагностический вопрос и интервенция), папка одна, полный список этапов — в многозначном поле `stage-fit`.
3. Внутри `02-intervention` алгоритм кладётся в папку своего семейства (мишень I–V). Семейства открыты: новый алгоритм добавляется при совпадении контрактов.
4. Материал берётся из `../knowledge/` (канон); цитаты сверяются с `~/work/Dielts/work/chapters/*.txt` по маркерам страниц. PDF в волт не копируется.
5. Исходный книжный вариант (`version-kind: original`) не затирается модификациями (`adapted`); версии живут рядом в одной папке.
6. Имена файлов: `alg-<slug>.md` (slug латиницей).
7. INDEX.md появляется при первом наполнении; в нём, кроме выборок по семействам и этапам, строится и вид «по главам книги» (по полю `source`).
8. **Контракты данных (папка `contracts/`).** Контракты входа и выхода модуля живут в `contracts/<тип>/`, каждый контракт — своя папка: `<тип>.yaml` (машинное представление — канон контракта, правится первым), `<тип>.md` (заметка: подробно, со ссылками), drawio (онтология типа, если есть). Заводится при наполнении. Подмодуль (блок модуля, например «Разбор» в `01-diagnosis`) оформляется отдельной папкой с README и ссылается на контракты входа/выхода предикатами `requires` / `fills` по полям карты; собственных контрактов у блока нет — промежуточные состояния заполняемого объекта контрактами не являются. В контракте — только механически проверяемые условия порта; семантика входа — работа блоков модуля, не условие приёма. Потребитель из другого модуля ссылается на контракт производителя (например, вход `02-intervention` → `../01-diagnosis/contracts/map/`).

## Frontmatter алгоритма (обязательные поля)

`id`, `module` (путь папки без `modules/`, например `02-intervention/f4-frame`), `type: algorithm`, `input`, `output`, `source` (глава/страницы издания 2010), `status`, `version-kind: original | adapted | composed`, `created`/`updated`.

Дополнительные: `target-class` (I–V, для интервенционных), `stage-fit` (вычислимо из контрактов, может быть многозначным), `mechanism` (один из 6), `channel` (вербальный / субмодальный / пространственный / реляционный), `layer: state` (для алгоритмов `00-states`).

## Контракт данных (`contracts/<тип>/`) и README блока

**YAML** (`<тип>.yaml`): `id` (`contract-<slug>`), `module` (путь папки), `direction: input | output`, `data-type`, `produced-by` / `consumed-by`, машинные поля контракта (тип, поля, enum, длины…), `ontology` — ссылка на место онтологии, если она уже описана (например, канон §4).

**Заметка** (`<тип>.md`): frontmatter `type: contract-note`, `contract: <id>`; тело — подробное пояснение со ссылками на канон и главы. Онтология типа — drawio-файл в той же папке.

**Блок** (README папки `b1-…`): frontmatter `type: block`, `parent: module-<…>`, `contract: {input: {ref, requires}, output: {ref, fills}}`.

Эталоны: `01-diagnosis/contracts/phrase/`, `01-diagnosis/contracts/map/`, `01-diagnosis/b1-parse/README.md`.
