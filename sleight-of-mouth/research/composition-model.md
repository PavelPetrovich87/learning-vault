# Композиционная модель (закреплена как рабочая схема)

**Статус:** фиксированная рабочая архитектура проекта от 2026-08-29, включая словарь (формальный регистр). Вся дальнейшая работа (модули, алгоритмы, композиции) строится в терминах этой модели. Развитие — **расширением в приближении** (zoom-in) по мере прохождения материала книги: новые алгоритмы добавляются в семейства, карта обрастает полями, композиции множатся. Пересборка схемы не планируется.

Происхождение алгоритма перенесено из структуры папок в поле `source`.

## 1. Словарь (зафиксирован 2026-08-29)

Формальный регистр, единый для карточек, индексов, схем и обсуждений. Рабочие метафоры обсуждения («кирпич», «гнездо», «удар», «разъём», «слот», «коробка») **упразднены** и в материалах не используются.

| Термин | Значение |
|---|---|
| **Алгоритм** | Единица библиотеки с двумя контрактами — входом и выходом |
| **Тип данных** | Объект, передаваемый между алгоритмами; его тип = совместимость стыковки. Четыре типа: **фраза → карта → сдвиг → закреплено** |
| **Мишень** | Место в структуре убеждения, по которому работает интервенция. Пять штук у любого убеждения (см. §4) |
| **Уязвимость** | Состояние мишени. Жизненный цикл: потенциальная (до диагностики) → подтверждённая `▲` (после) → пересмотр (после каждого применения) |
| **Семейство** | Набор взаимозаменяемых алгоритмов под одну мишень |
| **Применение** | Использование одного алгоритма по подтверждённой мишени + обязательная перепроверка карты после |
| **Этап** | Место в конвейере: диагностика → интервенция → интеграция. Свойство порядка; для алгоритма выводится из его входа/выхода |
| **Модуль** | Этап конвейера — папка библиотеки: `00-states` / `01-diagnosis` / `02-intervention` / `03-integration` (поправка 2026-08-29). Происхождение алгоритма хранится в поле `source` |
| **Композиция** | Конкретная цепочка алгоритмов, собранная по правилам стыковки |

## 2. Две структуры и их этажи

Проект держится на двух **несмешиваемых** осях:

- **Этапная ось** (порядок): диагностика → интервенция → интеграция. Живёт в **композициях** — задаёт, в каком порядке идут алгоритмы. Этап алгоритма выводим из его контрактов (фраза→карта = диагностика; карта→сдвиг = интервенция), поэтому этапной классификацией алгоритмов не является.
- **Структурная ось** (мишени): пять мест работы в убеждении. Это **не классификация техник, а схема объекта** — система типов данных библиотеки. Мишень существует в карте ещё до выбора алгоритма.

Обсуждение «объединять ли оси» закрыто: **объединение живёт в объекте (карта убеждения), а не в таблице**. Мишень — ключ join между картой и библиотекой: диагностика пишет в карту «уязвима II», селектор по этому ключу обращается к семейству II.

Таблица соответствия ролей:

| | Мишень I | II | III | IV | V |
|---|---|---|---|---|---|
| **Диагностика** | вопросы причины/намерения | кванторы, цена цели, иерархия | распознавание чанков | «как узнаёшь?» | экспликация допущений |
| **Интервенция** | №1, №2 | №3, №8, №11, №12 | №4, №5, №6 | №7, №9, №10 | №13, №14 |
| **Интеграция** | почти пусто — объект другой: строится структура **нового** убеждения (проверки «потому что» = его основания) | | | | |

## 3. Четыре типа данных и конвейер

```
фраза ─►[диагностика]─► КАРТА ─►[интервенция]─► СДВИГ ─►[интеграция]─► закреплено
```

- Диагностические алгоритмы заполняют карту и помечают уязвимости.
- Интервенционные алгоритмы берут карту с подтверждённой мишенью, дают сдвиг.
- Интеграционные алгоритмы работают с **другим типом** — кандидатом на новое убеждение: строят его основания (соединительные слова), закрепляют состояние (якорение), проводят по циклу (6 позиций), проверяют экологию.

## 4. Карта убеждения (центральный тип данных)

```
КАРТА УБЕЖДЕНИЯ
  тип:      CEq («А = Б») | C-E («А → Б»)      ← меняет чтение мишеней I–II
  A:        основание (причина / определяемый термин)
  B:        следствие (ценность / определение)
  мишень I   основание     — / ▲ / ▲▲
  мишень II  следствие     — / ▲ / ▲▲
  мишень III масштаб       — / ▲ / ▲▲
  мишень IV  рамка         — / ▲ / ▲▲
  мишень V   мета          — / ▲ / ▲▲
```

Таблица мишеней:

| Мишень | Место в убеждении | Маркер уязвимости (что видит диагностика) | Алгоритмы в семействе (старт: гл. 9) |
|---|---|---|---|
| I Основание | звено A — причина/определение | причина — не факт, а интерпретация | №1 Намерение, №2 Переопределение |
| II Следствие/ценность | звено B — результат | кванторы общности, «цена цели», конфликт критериев | №3 Последствия, №8 Другой результат, №11 Противоположный пример, №12 Иерархия критериев |
| III Масштаб | размер кусков A и B | монолитный ярлык, «всё или ничего» | №4 Разделение, №5 Объединение, №6 Аналогия |
| IV Рамка | контейнер: время, карта мира, способ проверки | один эпизод = вся жизнь; размытая верификация | №7 Размер фрейма, №9 Модель мира, №10 Стратегия реальности |
| V Рефлексивная | само утверждение как объект | правило нарушает само себя; убеждение об убеждении | №13 Примени к себе, №14 Метафрейм |

Нюанс чтения: для C-E («А → Б») мишени I–II — буквально звенья причины и следствия; для CEq («А = Б») звено — определение: I = переопределение термина (формальная причина), II = переоценка ценности, которую определение обслуживает.

## 5. Правила сборки (композируемость)

1. **Стыковка:** два алгоритма стыкуются ⟺ выход одного совпадает по типу со входом другого.
2. **Замена:** внутри семейства алгоритмы взаимозаменяемы (одинаковые контракты); между семействами — нет. Семейства открыты: модификации и новые разработки добавляются в семейство при совпадении контрактов.
3. **Серия применений:** мишеней может быть несколько — применения идут серией, **после каждого — перепроверка** (карта изменилась: мишень могла закрыться, вскрыться новая). Практический предел серии — 2–3 применения: дальше это спор, укрепляющий убеждение.
4. **Переход к интеграции** — условный: «мишеней не осталось».
5. **Состояния — сквозной слой**, не этап: состояние — «вместилище» убеждения (гл. 7), им композиция управляет на всех трёх этапах.
6. **Граница диагностика/интервенция проницаема** по устройству книги: диагностические вопросы сами являются паттернами («Как ты узнаёшь…?» = №10). Композиции могут использовать диагностический вопрос как интервенцию, роли в архитектуре не смешиваются.
7. **Цикл, а не линия:** после серии применений и в интеграции действуют обратные рёбра (цикл 6 стадий гл. 7; «вера» = экологический контроль в центре).

## 6. Пример собранной композиции

Фраза: «Я никогда не выучу английский, потому что у меня нет способностей».

| # | Алгоритм (модуль) | Вход → выход |
|---|---|---|
| Д1 | Парсер CEq/C-E (гл. 6) | фраза → тип C-E, A=«нет способностей», B=«не выучу» |
| Д2 | Детектор кванторов (гл. 6) | «никогда» → мишень II ▲▲ |
| Д3 | 4 вопроса-причины (гл. 6) | причина формальная → мишень I ▲ |
| И1 (применение 1) | №11 Противоположный пример (гл. 9) | карта(II) → сдвиг «уже знаешь 200 слов — значит, учишь» |
| — | перепроверка | мишень II закрыта частично, I ▲ осталась |
| И2 (применение 2) | №2 Переопределение (гл. 9) | карта(I) → «"нет способностей" = "не нашёл свой метод"» |
| — | перепроверка | мишеней нет → интеграция |
| У1 | Проверка соединительными словами (гл. 6) | сдвиг → основания нового убеждения |
| У2 | Цикл 6 позиций (гл. 7) | закреплено + экология |

Замена №11 → №8 на шаге И1 валидна (одно семейство); замена №11 → №10 — нет (мишень IV в карте не уязвима: тип входа не тот).

## 7. Как модель ложится на будущее INDEX и frontmatter

- **Модули** — этапные папки библиотеки (`00-states`…`03-integration`; поправка 2026-08-29 — исходно планировались тематические по главам). Происхождение алгоритма — `source`; семейства мишеней — подпапки `02-intervention`; вид «по главам книги» строит INDEX по полю `source`.
- **Frontmatter алгоритма:** `input` / `output` (контракты — главное), `target-class` (мишень, для интервенционных), `stage-fit` (вычислимо из контрактов, может быть многозначным), `mechanism` (один из 6), `channel` (вербальный / субмодальный / пространственный / реляционный).
- **Композиции** — потребители обеих осей: этапная задаёт скелет, данные карты (мишени) — выбор алгоритмов, ресурсный слой состояний обслуживает всё.

## 8. Принцип развития (zoom-in)

Схема фиксирована на текущем уровне детализации и **углубляется приближением**, по мере прохождения материала книги:

- новый паттерн/модификация → алгоритм в соответствующее семейство;
- новое диагностическое наблюдение → поле карты или маркер уязвимости в таблице §4;
- новый прикладной сценарий → композиция (самопомощь, коучинг, защита от манипуляций…);
- исходный книжный вариант (`original`) не затирается модификациями (`adapted`) — версии живут рядом в модуле.

Ничего не выбрасывается; изменения расширяют семейства и карту, а не меняют оси.
